# 本土化字幕流水线

## 目标

把校对完成的源语字幕转换为可审校的目标语字幕和配音台词。源语字幕条只负责提供原文、人物和时间证据，不要求目标语逐条对应。

当前首个目标语言为简体中文。语言代码、提示词输入和任务参数保持独立，后续可增加其他目标语言，不把中文规则写进通用数据结构。

## 当前已落地：本土化初稿

任务名称：`生成本土化字幕初稿`

1. `理解原文与人物`
   - 汇总主题、时代、场景、人物关系、情绪和说话习惯。
   - 人物证据不足时使用中性口吻，不编造口头禅。
   - 原文超过上下文分析预算时，按开头、中段、结尾分布式取样，不把模型输入无限放大。
2. `查证文化与背景`
   - 仅在专名、历史文化、制度或事实存在误译风险时联网。
   - 保存问题、查证目的、来源、结论和采用方式。
   - 每个目标语片段必须声明实际使用了哪项查证及其影响；没有直接影响时明确显示“仅参考，未直接采用”，不能用来源数量冒充有效结果。
3. `生成中文表达`
   - 先把校正后的源文整理成连续语义包，全文一次提交给 LLM。
   - 只有源文超过 24000 字符时才按连续语义章节拆分；每章携带全文理解结果及前后章节锚点，不按单句零碎请求。
   - 主生成请求只包含语义包 ID、人物和原文，不包含毫秒时间、词级时间或 word ID。
   - LLM 先按完整节目理解论述、人物口吻和前后照应，再返回可直接配音的自然中文；输入语义包不是逐句翻译单位。
   - 上屏字幕由同一份中文口播文本派生，省略普通逗号和句号；配音文本保留呼吸和语气标点。
4. `安排字幕分段与时间`
   - 代码把中文口播按自然语义拆成短句，再用单调跨语言对齐映射到源语语义单元。
   - 词级时间只在本地用于顺序、停顿和初始边界，不发送给中文生成模型。
   - 优先使用强制对齐后的源语逐词时间，缺失时回退到源语字幕范围；最终生成互不重叠的初始时间。
5. `对照原文复核时间线`
   - 第一次稀疏终审只检查数字、专名、否定、因果、人物口吻和明确翻译腔，不重写已经自然的中文。
   - 合并时间后，长时间线只选择一个最多 180 条的连续高风险窗口做稀疏语义检查，窗口外仍由本地规则检查来源覆盖、数字、顺序、时长、字数和阅读速度。
   - 180 条及以下的短时间线先让 LLM 只返回少量问题 ID，确有问题时再局部修复；输出截断则直接回退到本地硬校验。
   - 时间线终审只能返回中文文本替换，不能修改时间、顺序、ID 或来源；代码再次验证数字、顺序和覆盖。
6. `写入本土化字幕轨`
   - 原子写入独立本土化字幕轨、上屏字幕、配音台词和来源关系。
   - 源字幕在任务期间变化或任务被取消时，不提交生成结果。

每一步都保存独立耗时、可读总结、关键指标和结果明细。生成过程中会把初稿、已满足最短时长的初步时间和复核结果依次预览到时间线，但用户编辑保持锁定，完成后才进入可编辑状态。

## LLM 请求预算

常规完整任务使用少量整篇请求：

1. 全文理解与是否需要查证。
2. 全文无时间中文本土化。
3. 中文表达稀疏终审。
4. 时间线使用一次稀疏问题检测；超过 180 条时只检查一个高风险连续窗口，发现明确问题时再增加一次局部修复。

常规全文能放入安全预算时始终保持单次生成；只有超限才连续分章。流程不做无上限的“复查再微调”循环；只有结构化质量门发现明确问题时才修改，仍不满足硬约束则停止写入并显示问题。诊断会记录源字符数、请求体大小、分章数、请求数及长时间线实际复核范围，任务面板不得把风险窗口误称为全文复核。

## 真实项目 POC

2026-07-16 使用 11 分钟项目验证 v9 流程：327 条源字幕、2070 个对齐词整理为 29 个全文语义包，源词覆盖完整且顺序单调。全文中文生成约 75 秒，中文稀疏终审约 23 秒，231 条合并字幕的两批并行时间线复核约 93 秒；相比旧流程约 36 分钟，模型处理降到分钟级且请求次数固定。

时间线复核抓出了背景替换与打响指重复、动作和时间状语颠倒、`frame` 错配、`zoom out` 方向错误、`100%` 与 `4K` 数字归属等真实问题。旧 ASR 中一组连续词被压缩到近零时长，现由 ASR 层修复并在本土化时做只读兼容修复；剩余轻微阅读速度问题通过借用相邻静音解决，没有新增 LLM 请求。

## 双文本规则

每个目标语片段包含两份可编辑文本：

- `text`：上屏字幕。简短、易读，通常省略普通逗号和句号。
- `tts_text`：配音台词。保留有助于停顿、语气、疑问、犹豫或口语表达的标点和语气词。

两份文本必须保留相同的必需信息。人名、数字、日期、否定、比较和因果关系不得只出现在其中一份。

## 初稿时间约束

- 中文阅读速度：目标不高于 9 字/秒；生成时先按 9.5 字/秒尝试精简，精简不了但仍在约 12 字/秒以内时保留并提示试听，明显超过 12 字/秒才阻止写入。
- 单行建议不超过 16 个可见字符，最多两行。
- 显示时长：833 毫秒到 8 秒。
- 句末默认保留约 220 毫秒观察时间。
- 相邻字幕不得重叠。

这些规则只负责生成可编辑初稿，不冒充最终中文音频时间。
生成阶段会自动修复可借用相邻空间的短字幕；过长或阅读过快的字幕只会进入定向调整。仍无法满足约束时停止写入，并保留结构化失败信息，避免把明显不合格的初稿覆盖到现有轨道。

约束判断采用“代码守底线、LLM 做语义”的分工：

- 代码计算每条字幕的时长、可见字数、阅读速度、可用词级时间范围和建议最少段数，并负责覆盖完整、顺序稳定、时间不重叠等硬校验。
- LLM 在全文生成和稀疏终审中处理人物口吻、完整语义、中文自然度与相邻字幕语义错位；不负责生成时间戳。
- LLM 返回后由代码重新计算全部硬指标。数字、覆盖、顺序或时间规则不合格时列出实际数值并停止写入，不通过无限重试掩盖问题。

## 下一阶段：中文配音完成后的正式时间

```text
本土化初稿
→ 预估配音时长并改写过长片段
→ 生成中文配音
→ 对中文配音做逐字强制对齐
→ 按中文语义、停顿和阅读速度重新分段
→ 更新正式中文字幕时间
→ 质量门与人工试听
```

最终字幕时间必须来自实际中文配音音轨。计划使用 Qwen3 ForcedAligner 获取中文逐字时间，再进行第二次目标语分段；不能直接沿用英文字幕边界。

配音时长与可用窗口的比值建议：

- `0.90–1.10`：通过。
- `0.85–0.90` 或 `1.10–1.15`：优先改写、重新生成或调整安全边界。
- 超出 `0.85–1.15`：阻止自动交付。
- 不允许通过裁掉尾音来适配时间。

## 数据权威与并发规则

- `localized_subtitles` 是本土化字幕轨的可见主数据。
- cue 中的中文和 TTS 字段是下游兼容镜像，导入、编辑和清空时必须同步。
- 任务运行时锁定本土化轨，后端同样拒绝并发导入、编辑和清空。
- 每次生成保存源字幕指纹。原文、时间、人物、术语或场景变化后，旧本土化结果不得继续导出或生成配音。
- 取消任务必须在最终写入前可见；取消后的预览可以消失，但不得留下晚到结果。

## 后续模块边界

- `localization_research.py`：文化与背景检索、证据和译名决定。
- `speaker_profiles.py`：人物身份、语言口吻和声学表现。
- `localization_planner.py`：目标语语义块和首次分段规划。
- `duration_budget.py`：配音时长预测与改写策略。
- `tts_text_normalization.py`：数字、缩写、发音和引擎适配。
- `localized_alignment.py`：中文配音逐字强制对齐。
- `localized_subtitle_segmentation.py`：根据实际中文音轨生成正式字幕。

当前实现覆盖“本土化初稿”，不提前伪造配音后的正式时间。后续阶段沿用同一任务、预览、取消、耗时和结果明细契约。

## 多语言扩展边界

当前接口只接受 `zh-Hans`，但处理函数已经显式传递 `source_language` 和 `target_language`。开放第二种目标语言前，需要先把当前单轨状态迁移为按语言隔离的数据：

- 每种目标语言拥有独立的字幕轨、任务历史、来源指纹和质量门结果。
- 同一源语字幕可以同时存在多种目标语结果，生成新语言不得覆盖中文轨。
- 显示规则、阅读速度、标点和 TTS 文本规范由目标语言配置提供，不写死在通用映射层。
- TTS 音频与强制对齐结果按 `target_language + subtitle_id` 关联，避免不同语言共用 cue 镜像时互相覆盖。

本轮保留单目标语言数据结构，不把尚未完成的数据迁移伪装成多语言已支持。
