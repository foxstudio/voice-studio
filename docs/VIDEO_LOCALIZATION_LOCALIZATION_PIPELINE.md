# 本土化字幕流水线

## 目标

把校对完成的源语字幕转换为可审校的目标语字幕和配音台词。源语字幕条只负责提供原文、人物和时间证据，不要求目标语逐条对应。

当前首个目标语言为简体中文。语言代码、提示词输入和任务参数保持独立，后续可增加其他目标语言，不把中文规则写进通用数据结构。

## 当前已落地：本土化初稿

任务名称：`生成本土化字幕初稿`

1. `理解原文与人物`
   - 汇总主题、时代、场景、人物关系、情绪和说话习惯。
   - 人物证据不足时使用中性口吻，不编造口头禅。
2. `查证文化与背景`
   - 仅在专名、历史文化、制度或事实存在误译风险时联网。
   - 保存问题、查证目的、来源、结论和采用方式。
   - 每个目标语片段必须声明实际使用了哪项查证及其影响；没有直接影响时明确显示“仅参考，未直接采用”，不能用来源数量冒充有效结果。
3. `生成中文表达`
   - 允许连续源语字幕合并或拆分为不同数量的中文语义段。
   - 同时生成上屏字幕和配音台词，两者共享相同事实，但允许不同标点和口语细节。
   - 首轮完成后只挑出超过时长、字数或阅读速度预算的片段，合并为少量批次重新分段或压缩；不重复处理已经合格的内容。
4. `安排字幕分段与时间`
   - 优先使用源语逐词时间，缺失时回退到源语字幕范围。
   - 综合语义、停顿、阅读速度、最短显示时长和相邻边界，生成互不重叠的初始时间。
5. `复核语义与可读性`
   - 检查数字、专名、否定、因果和人物口吻。
   - 检查中文阅读速度、时长和标点，并保留修改前后与理由。
6. `写入本土化字幕轨`
   - 原子写入独立本土化字幕轨、上屏字幕、配音台词和来源关系。
   - 源字幕在任务期间变化或任务被取消时，不提交生成结果。

每一步都保存独立耗时、可读总结、关键指标和结果明细。生成过程中会把初稿、已满足最短时长的初步时间和复核结果依次预览到时间线，但用户编辑保持锁定，完成后才进入可编辑状态。

## 双文本规则

每个目标语片段包含两份可编辑文本：

- `text`：上屏字幕。简短、易读，通常省略普通逗号和句号。
- `tts_text`：配音台词。保留有助于停顿、语气、疑问、犹豫或口语表达的标点和语气词。

两份文本必须保留相同的必需信息。人名、数字、日期、否定、比较和因果关系不得只出现在其中一份。

## 初稿时间约束

- 中文阅读速度：正式初稿不高于 9 字/秒。
- 单行建议不超过 16 个可见字符，最多两行。
- 显示时长：833 毫秒到 7 秒。
- 句末默认保留约 220 毫秒观察时间。
- 相邻字幕不得重叠。

这些规则只负责生成可编辑初稿，不冒充最终中文音频时间。
生成阶段会自动修复可借用相邻空间的短字幕；过长或阅读过快的字幕只会进入定向调整。仍无法满足约束时停止写入，并保留结构化失败信息，避免把明显不合格的初稿覆盖到现有轨道。

约束判断采用“代码守底线、LLM 做语义”的分工：

- 代码计算每条字幕的时长、可见字数、阅读速度、可用词级时间范围和建议最少段数，并负责覆盖完整、顺序稳定、时间不重叠等硬校验。
- LLM 根据人物口吻、完整语义和自然停顿选择拆分位置或精简表达。只有阅读速度超限时，明确要求精简而不是无效地继续拆段。
- LLM 返回后由代码重新计算全部硬指标。最多三轮只处理仍有问题的片段；仍不合格时列出逐条实际数值和违反原因，并停止写入。

## 下一阶段：中文配音完成后的正式时间

```text
本土化初稿
→ 预估配音时长并改写过长片段
→ 生成中文配音
→ 对中文配音做逐字强制对齐
→ 按中文语义、停顿和阅读速度重新分段
→ 更新正式中文字幕时间
→ 质量门与人工试听
```

最终字幕时间必须来自实际中文配音音轨。计划使用 Qwen3 ForcedAligner 获取中文逐字时间，再进行第二次目标语分段；不能直接沿用英文字幕边界。

配音时长与可用窗口的比值建议：

- `0.90–1.10`：通过。
- `0.85–0.90` 或 `1.10–1.15`：优先改写、重新生成或调整安全边界。
- 超出 `0.85–1.15`：阻止自动交付。
- 不允许通过裁掉尾音来适配时间。

## 数据权威与并发规则

- `localized_subtitles` 是本土化字幕轨的可见主数据。
- cue 中的中文和 TTS 字段是下游兼容镜像，导入、编辑和清空时必须同步。
- 任务运行时锁定本土化轨，后端同样拒绝并发导入、编辑和清空。
- 每次生成保存源字幕指纹。原文、时间、人物、术语或场景变化后，旧本土化结果不得继续导出或生成配音。
- 取消任务必须在最终写入前可见；取消后的预览可以消失，但不得留下晚到结果。

## 后续模块边界

- `localization_research.py`：文化与背景检索、证据和译名决定。
- `speaker_profiles.py`：人物身份、语言口吻和声学表现。
- `localization_planner.py`：目标语语义块和首次分段规划。
- `duration_budget.py`：配音时长预测与改写策略。
- `tts_text_normalization.py`：数字、缩写、发音和引擎适配。
- `localized_alignment.py`：中文配音逐字强制对齐。
- `localized_subtitle_segmentation.py`：根据实际中文音轨生成正式字幕。

当前实现覆盖“本土化初稿”，不提前伪造配音后的正式时间。后续阶段沿用同一任务、预览、取消、耗时和结果明细契约。

## 多语言扩展边界

当前接口只接受 `zh-Hans`，但处理函数已经显式传递 `source_language` 和 `target_language`。开放第二种目标语言前，需要先把当前单轨状态迁移为按语言隔离的数据：

- 每种目标语言拥有独立的字幕轨、任务历史、来源指纹和质量门结果。
- 同一源语字幕可以同时存在多种目标语结果，生成新语言不得覆盖中文轨。
- 显示规则、阅读速度、标点和 TTS 文本规范由目标语言配置提供，不写死在通用映射层。
- TTS 音频与强制对齐结果按 `target_language + subtitle_id` 关联，避免不同语言共用 cue 镜像时互相覆盖。

本轮保留单目标语言数据结构，不把尚未完成的数据迁移伪装成多语言已支持。
