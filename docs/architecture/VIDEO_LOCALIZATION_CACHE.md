# 视频本土化缓存架构

状态：`current`

本页描述视频本土化工作台当前使用的可重建媒体缓存。它们不保存字幕、翻译、配音或项目真相；删除后项目仍完整，只是对应媒体需要重新准备。

## 四层职责

| 层 | 解决的问题 | 状态所有者 | 是否持久 |
| --- | --- | --- | --- |
| 视频兼容播放缓存 | 原片不能在当前浏览器产生画面时，按播放位置提供 H.264 fMP4 短片段 | 后端 `playback_proxy.py` | 是，可重建 |
| 时间线画面缓存 | 鼠标在时间线上移动时快速显示对应静态画面 | 后端 `preview_cache.py` | 是，可重建 |
| 浏览器播放缓冲 | 当前标签页已经取得并解码了哪些视频片段和音轨 | `PreviewVideoProxyController`、`SegmentedVideoSourceController` 与浏览器媒体元素 | 否 |
| 波形缓存 | 时间线快速绘制音量轮廓 | 后端 `waveform_cache.py` + 前端有界内存 LRU | 后端文件可重建，前端内存不持久 |

四层不得共用一个“完成百分比”。视频兼容片段、时间线精灵图和浏览器缓冲是三个不同事实；同一项目的两个标签页也可能有不同的浏览器缓冲范围。

浏览器媒体尚未挂载、尚未请求或空闲时表示“尚未缓存”，不表示正在加载。只有实际媒体加载、播放准备或明确的待完成任务才显示进行中；暂停后等待用户触发的音频输出也不是后台缓存任务。已取得的可播放范围不因浏览器继续下载其他范围而失效。

首次播放前不挂载音轨；开始播放后，暂停保留当前位置附近的有界音轨集合及已解码状态，不以暂停作为销毁资源的信号。跳转仍按预读窗口淘汰远处片段，项目或源媒体身份变化时清空会话；保留节点不允许暂停状态下自动发声。

自动化播放回归默认使用原生音频输出。测试机输出设备不可用时，可以显式设置 `VOICE_STUDIO_BROWSER_AUDIO=fake`，让需要播放时钟的隔离浏览器场景共用 Chromium 测试输出；日志必须记录该模式。该模式仍验证真实媒体读取、解码、播放时间与交互，不代表物理扬声器或主观听感通过，也不修改产品运行配置。

## 视频兼容播放模块

页面先用隐藏媒体元素请求稳定的 `source` URL，并以 `requestVideoFrameCallback` 收到浏览器实际提交的首帧作为直放依据；只有容器或音频进入 ready 状态不算成功。原片能产生首帧时，服务返回 `mode=source`，不创建代理；不能产生首帧时，页面提交当前播放位置，服务返回 `mode=segmented` 并优先生成该位置附近的片段。

公共入口只有以下意图级能力：

- 请求播放：提交 `source_playable`、目标时间范围和是否后台补齐。
- 读取状态：返回版本化 `VideoPlaybackProxyStatus`，不暴露本地路径。
- 读取片段：只允许按项目和片段序号读取已经原子发布的文件。
- 删除项目缓存：取消该项目任务并删除全部兼容片段。

当前状态契约是 `video-playback-proxy-status-v2`：

- `mode` 区分 `source` 与 `segmented`；`playable` 只回答请求位置当前是否可播。
- `requested_range`、`ready_ranges` 和 `active_segment` 描述真实覆盖和当前工作，不复用缩略图进度。
- `ready_segments / total_segments / progress` 描述后台兼容片段覆盖率；首段可播不等于后台已经完成。
- `revision` 固定一次源媒体/代理 generation。项目、源媒体或 generation 变化后，旧轮询结果必须丢弃。
- `partial` 是正常可播放状态，不是失败；单片段失败隔离记录，可由同一请求重试。

兼容片段为 4 秒、720p 以内、video-only H.264 High Profile Level 4.0 独立 fMP4。音频继续使用已有独立音轨节点，避免视频代理重复编码和传输音频。前端只在有界窗口内拉取目标段、三个后续段和一个回看段，并通过一个 MSE `SourceBuffer` 映射到全局时间线；跳转会提高新目标段优先级，不等待旧的后台游标。

旧 `variant=preview` 查询参数只作为读取兼容适配器保留，返回原片且不触发整片转码。生产代码不再存在“整片 H.264/AAC 转完后原子切换”的第二套视频代理算法。

## 时间线画面模块

公共入口只有查询状态、请求范围、请求全量、刷新画面、删除项目缓存和读取已完成精灵图。WebUI、REST/OpenAPI 和内部适配器都必须通过这些入口，不得各自实现生成、校验、重试或清理逻辑。

状态契约位于 `preview_cache_contracts.py`，当前版本为 `video-preview-cache-status-v1`：

- `state` 表示空、生成中、部分完成、完成或失败。
- `phase` 只表示排队、生成画面块、失败或取消；时间线画面不准备视频代理。
- `active_chunk` 只有真正生成某个画面块时才有值。
- `error`、`retryable`、`started_at` 和 `updated_at` 用于失败恢复和停滞判断。

单个画面块临时失败时原地重试一次；第二次仍失败才结束本次任务。长视频全量生成使用单向块游标，不在每块之后重扫全部历史。容量回收保护所有活跃任务根目录，损坏或不完整文件不会被报告为 ready。

## 媒体进程与资源调度

`media_assets.py` 只负责 ffprobe/ffmpeg 进程和原子文件发布；`playback_proxy.py` 与 `preview_cache.py` 分别拥有自己的任务状态和策略。视频片段与缩略图块通过 `media_work_coordinator.py` 共享一个进程级媒体工作槽，优先级固定为：当前播放位置、时间线画面、后台视频补齐。

调度只发生在有界单元之间，不中断正在运行的 FFmpeg：一个视频单元最多 4 秒，一个缩略图单元最多 10 秒。探测和生成必须有超时、取消信号和 `.part` 清理；单片段先尝试 VideoToolbox，再回退 libx264。源素材永远不能被缓存覆盖。

音频代理仍是独立浏览器兼容缓存。设置页把视频片段与音频代理统一归入“视频与音轨播放代理”的白名单清理范围；清理只遍历受管项目的真实 `preview` 目录，跳过符号链接，不删除源视频、分轨、字幕、配音或导出结果。

## 波形模块

同一音频、同一密度的并发请求共享一个进程内生成锁，只计算和写盘一次；锁在最后一个等待者离开后删除。低密度请求优先从已有高密度缓存做保峰降采样。损坏、截断或密度不匹配的 JSON 会删除并重建。

视频本土化时间线和语音合成页的受管参考音频编辑器复用同一个 `waveform_cache.py` 服务。前端先请求低密度预览，再按可见宽度和缩放请求细节密度，并共享有界内存 LRU、并发队列和同 URL 请求。只有真正不受后端管理的浏览器本地对象 URL 才使用前端解码兜底。

时间线片段以稳定 `clip_id` 保持组件身份，以版本化媒体与量化可见窗口 URL 保持波形资源身份。移动、裁切、切分、选择、播放头和框选只能更新直接受影响的片段或几何层，不得通过全局暂停、全量 key 或项目 revision 让未修改片段重挂载或重取波形。缩放和滚动只渲染带小幅 overscan 的可见窗口；密集缩放级别使用概览层，进入细节级别后再按屏幕像素密度渐进请求波形。播放器同样只挂载活动片段和有限预读片段，媒体失败只递增对应资源的恢复 revision。配音历史分页只读取记录元数据，单条波形进入可见区附近后才请求，屏幕外记录不得批量触发波形读取。

播放就绪状态仍保存完整分块，供播放头做精确命中；缓存条只是可见读模型。缓存条先按
可见时间窗过滤，再按容器像素预算聚合为有界数量，聚合桶保留最严重状态和阻塞原因。
因此长视频概览不会为每个底层缓存块创建一个 DOM 节点，放大后仍恢复精确分块。

配音历史使用单次取得的 320 点音量轮廓，按容器宽度保峰降采样绘制，最多 320 根波形柱；
调整面板宽度只重新绘制，不重复请求或解码音频。尚未取得波形时不绘制虚构的音量轮廓。
历史波形按单条峰值归一化展示声音轮廓，静音保留基线；它不是绝对音量表，不改变缓存数据、音频或播放增益。

时间线裁切或移动后，同一音频的已加载细节波形若覆盖新的可见源区间，继续使用它等待新细节，
不先降级为全文件粗预览。纯移动不改变媒体身份；已有波形与新可见源区间部分重叠时保留重叠部分，后台补齐细节，不清空整段。
有界缓存中已有覆盖请求范围且密度足够的数据时直接复用，不重复请求。媒体身份变化或已有数据与新区间完全不相交时才使用预览，避免错用旧音频或窗口外的数据。
切分后新挂载的片段也从同一个有界缓存复用覆盖源区间且采样密度足够的波形；媒体版本必须一致，只有缓存不足时才请求当前窗口的细节。

已缓存波形的画布在 DOM 更新后的绘制阶段直接绘制，不再额外延迟一个动画帧，避免重新挂载后先显示零宽画布。波形绘制与音频播放准备相互独立，验证时分别检查画布可见性和媒体节点连续性。

完整时间线投影与编辑回执均由 `timeline_clip_identity.with_generation_identity` 在内部路径脱敏前提供 `has_audio_source`。前端不以回执是否包含内部路径判断音频是否存在；播放节点与媒体 URL 使用结果或 generation 身份，位置保存及路径脱敏不改变资源身份。旧投影仍兼容已有路径或切片来源字段；此字段只描述源引用存在，不替代真实媒体就绪检查，也不写入可编辑的切片来源字段。

## 生命周期

- 导入或替换源视频后，取消旧播放/画面任务并清除该项目的旧可重建缓存。
- 页面打开后先探测原片；兼容播放片段与时间线画面都只优先请求当前播放位置。时间线
  画面在悬停或跳转时按块补建，只有用户显式“刷新缓存”才启动全线重建，避免打开长
  视频后持续占满媒体工作槽和 CPU。
- 鼠标进入未完成的缩略图范围时，只提高该画面块优先级，不改变播放片段状态。
- 跳转到未缓存位置时提高新视频片段优先级；已经发布的其他片段继续可读。
- 项目重置和删除先取消任务，再清理播放片段、时间线画面和项目波形缓存。
- 页面“刷新缓存”重载当前媒体并重建时间线画面，不删除音频代理。
- 后端重启后从磁盘重建 ready 覆盖；只丢失进程内队列。未完成片段可由下次请求继续生成。

## 扩展约束

- API 不返回缓存绝对路径；文件访问必须使用 project-scoped 资源端点。
- 播放代理、时间线画面和波形分别统计；只有设置页明确展示口径时才汇总。
- 长视频状态优先使用紧凑范围和增量元数据，避免高频轮询扫描或传输逐片段明细。
- 新调用方扩展同一版本化契约和应用服务，不新建第二套代理算法或状态机。
