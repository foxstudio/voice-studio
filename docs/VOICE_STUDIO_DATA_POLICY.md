# Voice Studio 本地数据与模型规则

仓库只保存代码、文档、测试和“去哪里下载模型”的清单。模型权重、音色、生成结果、项目文件、数据库、API Key 都不进入 Git。

## `~/VoiceStudio` 目录

| 目录 | 用途 | 清理规则 |
|---|---|---|
| `config/` | 设置和 SQLite 数据库 | 核心数据，不自动删除 |
| `voices/` | 已保存到音色库的长期参考音 | 长期保留，只能由用户明确删除 |
| `assets/reference-audio/custom/` | 生成页临时上传的参考音 | 有任务/历史/预设等引用时保留；最后一个引用删除后回收，未使用上传 7 天后回收 |
| `assets/seed-audio/images/` | Seed Audio 等模型使用的图片输入 | 有任务/历史引用时保留；孤立上传 7 天后回收，内置预设长期保留 |
| `projects/` | 视频本土化等项目及其素材、轨道和导出 | 删除项目时再联动清理 |
| `outputs/` | 合成结果 | 删除对应生成记录时删除 |
| `exports/` | 用户明确导出的交付文件 | 不自动删除 |
| `cache/` | 波形、目录缓存、对齐日志等可重建数据 | TTL + 容量上限 + LRU 自动维护 |
| `models/` | 模型权重 | 不自动删除，不提交 Git |
| `engines/` | 外部引擎运行时或指向它们的软链接 | 不自动删除，不提交 Git |
| `logs/` | 应用日志和受管常驻模型 worker 日志 | 用户显式清理；worker 日志单文件最多 5 MB，并保留 2 份轮转 |
| `reports/audits/` | 人工运行数据审计脚本时生成的报告 | 可重建，可人工清理 |
| `backups/` | 迁移或维护前留下的保护副本 | 确认不再回滚后人工清理 |

旧版 `seed_audio/assets/` 继续兼容读取，但新文件统一写入 `assets/seed-audio/images/`。
旧版 `manifests/` 只作为迁移兼容目录；新的审计报告统一写入 `reports/audits/`。

## 唯一主数据库

- 正式运行时唯一主数据库是
  `VOICE_STUDIO_DATA_DIR/config/voice_studio.db`，默认即
  `~/VoiceStudio/config/voice_studio.db`。
- `backups/` 中的数据库是维护前保护副本，不参与运行时读写；旧版数据根目录下的
  `voice_studio.db` 不再作为兼容运行入口。
- 自动化测试和开发服务必须把 `VOICE_STUDIO_DB_PATH` 与所有可写数据目录统一指向
  本次运行独占的临时根目录，不能读取或修改用户主数据库。

## 项目删除与手动移除目录

- 页面中的“删除项目”是完整删除入口：先检查运行中的任务，再清理项目目录、
  项目记录、生成历史和项目专属缓存；仍被其他项目使用的共享素材会保留。
- 在文件管理器中直接删除 `projects/` 下的项目目录，只代表项目包已经不在本机。
  本土化历史菜单会据此隐藏项目，但不会自动删除 SQLite 中可能仍用于审计的任务
  和历史记录。
- `config/`、`outputs/`、`cache/` 不应整体搬进单个项目目录。它们分别承担全局
  索引、生成结果和可重建缓存职责；项目删除由统一应用服务按项目 ID 联动清理。

## 开发与测试数据隔离

- 测试、调试、浏览器验收和基准运行使用同一个、由当前运行独占的临时数据根目录；
  数据库、项目、输出、导出、素材、缓存和日志都必须派生到该临时根目录。
- 临时根目录必须位于产品正式数据目录和代码仓库之外，并由 fixture、上下文管理器
  或明确的会话清理钩子在成功、失败、取消和超时路径中回收。
- 开发快照只用于定点重放，不得被正式任务读取。验收完成后必须删除快照、切片、
  测试项目、调试日志和测试导出；不得把它们留在 `~/VoiceStudio/projects` 或
  用户交付目录中。
- 开发任务收尾时必须核对正式数据目录是否出现新的测试命名项目或孤立目录；归属
  未确认时先报告，不得用宽泛目录删除代替精确清理。

## 模型和引擎为什么分开

- `models/` 是权重，通常几个 GB，可以重新下载。
- `engines/` 是运行这些权重的代码和 Python 环境，也可以是指向其他位置的软链接。
- 二者用途不同，不合并。一个引擎可能共用多个模型，一个模型也可能由不同运行时调用。

新安装默认把模型放在 `~/VoiceStudio/models/`，不放进代码仓库。全局
`VOICE_STUDIO_MODELS_DIR` 会覆盖设置页中的模型目录；单模型变量只覆盖该模型的读取位置。
读取顺序固定为“单模型变量 → 统一受管目录 → 已登记旧目录 → Hugging Face 只读缓存”。
空目录或残缺模型不会遮住后方完整副本。外部模型只登记并读取，不会在启动或生成时
自动复制几 GB 的权重；当受管目录缺少时，界面会明确告知建议位置。

模型路径分成两种用途：安装器只取得受管写入路径，永远不向旧目录或外部缓存写文件；推理和健康检查取得可读路径，可以按明确顺序兼容旧安装。新增模型能力不得把这两种用途重新混成一个入口。

路径设置支持 `~`、`$NAME` 和 `${NAME}`。当 `VOICE_STUDIO_MODELS_DIR` 接管时，设置页显示
实际目录并设为只读，避免用户保存了一个实际不会生效的值。移动模型后，常驻对齐 worker
会按 Python、模型路径和设备变化自动重启，不继续使用旧位置。

外部引擎路径按以下顺序查找：环境变量、`~/VoiceStudio/engines/<engine>`、仓库同级的 `tts-engine-lab/<engine>`。已有模型和引擎不必复制，可继续使用环境变量或软链接。修改模型根目录目前只影响之后的默认位置，不会隐式搬迁或删除原目录。

只有同时具备已核验模型许可、明确许可标识、HTTPS 官方页和下载源，以及固定 revision 或 SHA-256 的受管模型，才允许一键下载。权重许可不明、来源不安全或完整性信息不足时，界面只提供官方跳转和具体阻断原因，不发起自动下载。

常驻 TTS worker 的 stderr 会持续排空，避免模型输出填满子进程管道。受管 worker 日志位于
`logs/.voice_studio/`；F5-TTS、CosyVoice 等外部运行时仍在各自根目录的
`.voice_studio/` 下保存日志。两类日志均使用 `0600` 权限、5 MB 单文件上限和 2 份轮转，
错误提示只读取文件末尾的有界片段，不把整份历史日志载入内存。

## 自动清理边界

自动清理只处理可重建缓存。音色库、ASR 原始上传、项目、生成结果、导出、模型和引擎运行时永远不进入自动缓存清理范围。

默认缓存策略为 30 天 TTL、可重建缓存合计最多 1 GB；按最后访问时间优先淘汰旧文件。可用 `VOICE_STUDIO_CACHE_TTL_DAYS`、`VOICE_STUDIO_CACHE_MAX_BYTES` 和 `VOICE_STUDIO_ORPHAN_ASSET_TTL_DAYS` 调整。

启动清理会在 API 就绪后转入后台，不让大缓存目录拖慢启动。同一缓存根目录同时只有一个进程执行维护；其他进程会跳过本轮，不会等待。可在 `/api/health` 的 `startup_maintenance` 中查看当前状态和错误数。
