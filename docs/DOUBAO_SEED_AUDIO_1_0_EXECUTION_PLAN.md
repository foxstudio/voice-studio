7. **清理后复测**：再次运行当前任务的验证，防止功能依赖已删除的临时产物。
8. **检查范围**：用 Git 状态和 diff 确认没有修改无关文件。

## 2. 最终目标

在现有“语音合成”页面中新增 Seed Audio 1.0 引擎。当用户选择该引擎时，页面参数区自动切换为 Seed Audio 专属界面；切换到其他模型时，继续使用原有模型界面。

最终体验：

```text
选择引擎
  -> 选择生成方式
  -> 选择或上传参考素材
  -> 编写生成描述
  -> 调整当前模型参数
  -> 提交生成
  -> 在现有任务和生成记录中查看、下载、复用
```

Seed Audio 支持三种生成方式：

- 文字描述
- 参考声音
- 参考图片

本项目必须形成可持续扩展的模型面板机制。以后增加或修改某个模型的参数时，不应修改其他模型的专属逻辑。

## 3. 非目标

- 不创建新的独立页面。

- 不承诺生成结果逐字稳定、固定时长或完全复刻参考素材。
- 不把控制台中抓取到的临时案例媒体直接打包进项目。
- 不一次性重写所有旧模型。
- 不在第一版引入复杂富文本编辑器。
- 不改变现有视频本土化、批量生成和长文本流程，除非为了兼容新请求契约做必要的加法修改。
- 不在未获得明确授权时调用可能产生费用的真实 API。

页面导航首期继续叫“语音合成”。如果未来接入更多音乐、环境音或音效生成模型，再单独评估是否改名为“语音与音频生成”。

## 4. 官方能力基线

### 4.1 官方来源

- 音频生成 HTTP：<https://docs.volcengine.com/docs/6561/2550782?lang=zh>
- 豆包语音合成模型 2.0 音色列表：<https://www.volcengine.com/docs/6561/1257544?lang=zh>
- 计费说明：<https://docs.volcengine.com/docs/6561/1359370?lang=zh>

后续维护或重新进行云端兼容性验收时，必须重新核对以上页面；若官方文档变化，以最新官方文档和真实 API 验证为准，并同步更新本文。

### 4.2 已确认接口

- 方法：`POST https://openspeech.bytedance.com/api/v3/tts/create`
- 鉴权：新版控制台使用 `X-Api-Key`
- 模型：`seed-audio-1.0`
- 接口形态：非流式 HTTP
- 最大输出：120 秒
- 支持语种：中文普通话、英语
- `text_prompt`：必填，最多 3000 字符
- 返回：Base64 音频、临时 URL、时长、可选字幕
- 临时 URL：有效期 2 小时，必须及时下载到本地受管理目录

### 4.3 三种模式

#### 纯文本生成

- 不传 `references`
- 根据 `text_prompt` 生成完整声音场景

#### 参考音频生成

- 最多三条参考音频
- 每条最长 30 秒
- 每条不超过 10 MB
- 格式：`wav`、`mp3`、`pcm`、`ogg_opus`
- 每条参考项可使用以下一种来源：
  - `speaker`
  - `audio_data`
  - `audio_url`
- 同一参考项内，`speaker`、`audio_data`、`audio_url` 互斥
- `speaker` 可以是豆包语音合成 2.0 官方音色，也可以是声音复刻音色

#### 参考图片生成

- 只能一张图片
- 不超过 10 MB
- 格式：`jpeg`、`png`、`webp`
- 使用 `image_data` 或 `image_url`，二者互斥
- 图片不能与任何音频、`speaker` 混用

### 4.4 `@音频N` 引用规则

- 第一条参考声音对应 `@音频1`
- 第二条对应 `@音频2`
- 第三条对应 `@音频3`
- 编号由请求中 `references` 数组的顺序决定
- 后端最终只认识官方固定字符串，不认识本地文件名、音色名称或内部 ID

### 4.5 输出参数

| 参数 | 默认值 | 允许值或范围 | UI 分组 |
| --- | --- | --- | --- |
| `format` | `wav` | `wav` / `mp3` / `pcm` / `ogg_opus` | 基础 |
| `sample_rate` | `24000` | 8000 / 16000 / 24000 / 32000 / 44100 / 48000 | 基础 |
| `enable_subtitle` | `false` | `true` / `false` | 基础 |
| `speech_rate` | `0` | -50 到 100 | 高级：整体后处理 |
| `loudness_rate` | `0` | -50 到 100 | 高级：整体后处理 |
| `pitch_rate` | `0` | -12 到 12 | 高级：整体后处理 |
| `aigc_watermark` | `false` | `true` / `false` | 高级：水印 |
| `aigc_metadata.enable` | `false` | `true` / `false` | 高级：水印 |
| 制作和传播元数据 | 空 | 字符串 | 开启隐式水印后显示 |

注意：官方没有“指定目标时长”参数。页面只能展示最长 120 秒的限制，不能提供一个无效的目标时长控件。

### 4.6 计费提示

- 后付费参考价：1 元/原始生成分钟
- 计费以 `original_duration` 为准
- 调整语速不减少计费时长
- 正式版默认支持 5 并发

页面只能做“预计费用”提示，最终费用以官方账单为准。

## 5. 真实 API 验收与可延期规则

官方文档没有完全说明以下行为。不得靠猜测写死产品规则。

2026-07-11 验收时，本地接口返回 `doubao_api_key_configured=true`、`cloud_enabled=true`。这只是历史状态快照；未来补测必须重新检查布尔状态，禁止读取或输出 Key 原文。

未来补充兼容性验证时，应通过正式应用任务链进行低成本、受控的真实请求，并遵守：

- API Key 已在设置中配置，且不会打印到日志
- 使用最短、最低成本测试样本
- 不进行无上限重试、批量压力测试或无关质量评测
- 记录本轮实际请求数量和预计成本

- Key 未配置、失效或权限不足
- 试用额度或账户余额不足
- 服务尚未开通
- 网络或官方服务持续不可用
- 官方返回无法安全判断是否已扣费的异常

真实 API 暂时不可用时，以下本地与 mock 验证仍不能省略：

- schema 和参数边界测试
- mock client 和请求体快照测试

## 7. 已确认产品决策

### 7.1 页面归属

- Seed Audio 继续放在 `/generate`
- 不新增侧边栏页面
- 引擎选择仍使用现有引擎选择器
- 预设区应跟随当前引擎，并逐步调整为先选引擎、再看当前引擎预设

### 7.2 模式名称

页面使用：

- 文字描述
- 参考声音
- 参考图片

不使用“第四种官方音色模式”。官方音色或云端音色只是参考声音的一种来源。

### 7.3 参考声音槽位

- 固定最多三个槽位
- UI 始终显示槽位对应的 `@音频1`、`@音频2`、`@音频3`
- 第一版不支持自由拖动排序
- 删除正在被引用的槽位必须确认
- 空槽位不进入最终请求数组
- 提交前根据最终数组顺序编译官方引用编号

### 7.4 素材来源

每个声音槽位可来自：

- 音色库中的本地参考文件
- 豆包官方或已训练的云端 `speaker`
- 用户拖拽或选择的本地音频
- 受管理的预设素材

音色库中没有参考音频、授权状态不允许使用、格式或时长不合格的条目应置灰并说明原因。

若一个音色资产包含多条 `reference_audio_ids`，必须让用户选择具体文件，不能继续静默使用第一条。

### 7.5 参考音频编辑

- 不在页面上同时展开三个大型编辑器
- 每条参考声音卡片提供“编辑”按钮
- 点击后在共用弹窗或抽屉中打开同一个编辑器组件
- 裁剪必须非破坏性：保留原文件，记录当前选区和生成的片段文件
- 每个槽位拥有独立的裁剪、台词和状态

### 7.6 Prompt 引用

第一版不使用复杂富文本：

- 保留普通 textarea
- 输入 `@` 时弹出当前可引用声音
- 同时提供“插入引用”按钮作为稳定入口
- 选择后插入官方字符串 `@音频N`
- 下方显示已引用、未引用和无效引用
- 手写错误编号必须在生成前拦截

### 7.7 模式草稿

- 切换模式时保留各模式草稿，不静默删除素材
- 只提交当前模式的数据
- 图片模式不能提交任何声音参考
- 参考声音模式不能提交图片
- 重置当前参数不能删除用户素材，删除素材必须是独立操作

### 8.3 Engine UI Profile

- 支持的输入模式
- 创建默认状态
- 当前模式参数 schema
- 生成前校验
- `toRequest`
- `fromRequest`

找不到专属 Profile 时回退到 Generic Profile，继续使用现有 manifest 和 `ParameterPanel`。

### 8.4 标量参数与复杂布局的边界

- 后端 manifest 负责描述能力事实、默认值、范围和简单标量参数
- 前端 Profile 负责模式、素材、条件显隐、复杂布局和交互
- 不要把整个页面布局写成一个巨大的后端 UI DSL
- 不要把复杂多素材输入强行塞进通用 `ParameterPanel`

manifest 已增加以下能力事实：

- `input_modes`
- `max_reference_audio`
- `max_reference_image`
- `mutually_exclusive_inputs`
- `prompt_reference_syntax`
- `supported_output_formats`
- `supported_sample_rates`
- `max_prompt_chars`
- `max_output_seconds`

### 8.5 前端状态边界

公共状态只保留所有工作台都需要的数据，例如：

- `engineId`
- 任务状态
- 历史记录
- 当前结果播放器

模型状态使用按引擎隔离的容器或独立 store：

```text
engineStateById[engine_id]
```

不得继续给全局 `GenerateStoreState` 增加几十个 `seedAudioXxx` 字段。

### 8.6 后端实际目录

```text
backend/app/engines/
  base.py
  registry.py
  seed_audio/
    schemas.py
    adapter.py
    client.py
    assets.py
    validation.py
backend/app/api/
  seed_audio_assets.py
backend/app/services/
  engine_manifests.py
```

采用渐进方案：

1. task queue 优先查找新 Adapter Registry
2. 已注册引擎使用专属 schema、校验和请求构造
3. 未注册的旧引擎继续走当前兼容路径
4. Seed Audio 稳定后再逐步迁移旧引擎

不得为了接入一个新模型，一次性重写全部 task、batch 和 longform 队列。

## 9. 新请求契约

### 9.1 公共 envelope

Seed Audio 没有把所有专属字段继续加到 `GenerateRequest` 顶层，而是以兼容方式增加：

```text
engine_id
text
input_mode
input_assets[]
engine_parameters{}
```

旧字段在兼容期继续保留。

### 9.2 EngineInputAsset

已落地的公共素材字段包括：

```text
asset_id
type: audio | image | speaker
source: voice_library | upload | cloud_speaker | preset
file_id
voice_id
speaker_id
display_name
ref_text
source_file_id
clip_file_id
trim_start_ms
trim_end_ms
duration_ms
mime_type
size_bytes
license_status
```

安全要求：

- 前端只传 `file_id` 等受管理标识
- 后端根据 `file_id` 解析真实路径
- 不接受前端传入任意本地绝对路径
- 后端再次检查文件存在性、类型、大小、时长和授权状态

### 9.3 SeedAudioParameters

Seed Audio 使用自己的严格 Pydantic schema，至少包括：

- `format`
- `sample_rate`
- `enable_subtitle`
- `speech_rate`
- `loudness_rate`
- `pitch_rate`
- 水印配置

不应依赖全局 `speed` 自动猜测 `speech_rate`。前端、后端和历史快照中保持官方字段语义，必要的展示换算只放在 UI 层。

### 9.4 单次、批量和历史

首期先支持单次生成。

首期批量生成和长文本不支持 Seed Audio；请求会被明确阻止，不能静默使用错误路径。

历史与复用要求：

- 任务记录必须保存当前模式、素材摘要和 engine parameter snapshot
- “复用参数”必须能恢复当前模式、Prompt 和仍然存在的素材
- 素材已清理时应显示可理解的错误，不能恢复出一个看似可用的空任务

## 10. Seed Audio 页面规格

### 10.1 引擎区

- 引擎显示名：`豆包音频生成 Seed Audio 1.0`
- 类型：云端
- 描述：文字、参考声音或图片生成完整声音场景
- 显示云端上传和可能产生费用的提示
- 未配置 API Key 时，引导到设置页面

### 10.2 模式区

三个互斥选项：

- 文字描述
- 参考声音
- 参考图片

选择模式后只显示当前真正生效的输入和参数。

### 10.3 参考声音卡片

每个卡片显示：

- `@音频N`
- 名称和来源
- 时长、格式、文件大小
- 参考台词或简短说明
- 授权状态
- 试听
- 编辑
- 替换
- 删除

空卡片提供：

- 从音色库添加
- 选择云端音色
- 拖拽或选择文件

### 10.4 音色库选择

- 可搜索、试听
- 点击后添加到第一个空槽位；若用户从指定槽位打开，则添加到该槽位
- 本地音色需要选择具体 `reference_audio_id`
- 云端豆包音色使用 `speaker_id`
- 不兼容条目置灰并显示原因
- 添加只是建立引用，不复制原文件；保存预设包时再根据素材策略固化

### 10.5 参考音频编辑器

从现有自定义音色功能抽出：

- 波形
- 时间标尺
- IN / OUT
- 缩放
- 播放选区和循环试听
- ASR 识别
- 可编辑参考台词
- 原始文件和裁剪片段元数据

编辑器只处理一个 ReferenceAudioDraft，通过 props 和事件回传结果，不能直接修改全局单音色状态。

### 10.6 Prompt 编辑器

按模式显示写法说明。

文字描述模式建议说明：

```text
先写场景和环境，再写音乐、人物声音、情绪、实际对白和收尾音效。
```

参考声音模式建议说明：

```text
使用 @音频1～3 指定参考对象。编号必须与上方参考声音卡片一致。
```

图片模式建议说明：

```text
写清楚图片角色要说的内容、表达方式和希望生成的声音场景。
```

引用校验：

- 引用了空槽位：阻止生成
- 引用了 `@音频4` 或更大编号：阻止生成
- 有素材未引用：提示，可继续
- 删除已引用素材：二次确认
- Prompt 超过 3000 字符：阻止生成

### 10.7 参数区

基础参数始终显示当前模式真正支持的参数。

高级参数默认收起，并分组为：

- 整体声音后处理
- 字幕
- 水印和来源信息
- 开发者诊断信息（仅开发模式）

“恢复默认值”只恢复当前引擎、当前模式的参数，不删除素材，不影响其他引擎状态。

### 10.8 生成前检查

生成按钮附近显示：

- 当前模式
- Prompt 字数
- 参考素材数量和状态
- 输出格式和采样率
- 最大可能费用提示
- 云端上传确认

只有所有强制校验通过后才能提交。

## 11. 预设包设计

### 11.1 预设包字段

前端已新增按“引擎 + 模式”筛选的 `SeedAudioPresetBundle`；内置文字预设保存以下核心信息：

```text
preset_id
name
description
engine_id
input_mode
prompt_template
assets[]
reference_bindings[]
engine_parameters{}
tags[]
```

参考声音和参考图片预设保留素材与引用字段，但需等获得明确授权的媒体后再加入内置包。

### 11.2 预设分类

- 文字预设：Prompt + 参数
- 参考声音预设：Prompt + 声音素材 + 引用关系 + 参数
- 参考图片预设：Prompt + 图片素材 + 参数

建议原创分类：

- 单人知识旁白
- 双人悬疑对白
- 有声书场景
- 广告口播和配乐
- 游戏角色对白
- 环境音效场景

### 11.3 媒体策略

- 不把临时官方 URL 写入预设
- 不默认抓取控制台内部素材
- 自有或明确授权素材可以进入受管理预设目录
- 大文件优先使用首次使用时下载并缓存
- 缓存需要 checksum、来源、版本和失败提示
- 用户保存的预设不能只记录临时本地路径，应复制到受管理目录或引用稳定的 VoiceAsset / VoiceFile ID

| Seed Audio client | mock HTTP 请求体和响应测试 | 参数准确映射到官方字段，结果保存为真实文件 | 401/403、额度不足、超时、URL 过期、Base64 损坏 | 删除原始响应和临时输出后重跑 mock 测试 |
| 文字描述模式 | store、校验和 request snapshot | 页面无单声音控件，能够提交 3000 字以内 Prompt | 空 Prompt、超长 Prompt | 删除调试预设后重跑前端测试和浏览器 smoke |
| 基础/高级参数 | 边界值和默认值测试 | 控件值与最终请求一致，重置只影响当前模型 | 越界、格式不支持、水印字段不完整 | 删除临时参数分支后重跑参数契约测试 |
| 多参考声音 | 三槽位状态和后端数组校验 | 音色库、speaker、上传文件可分别加入并独立编辑 | 第四条、超 30 秒、超 10MB、授权不允许 | 删除裁剪残留和孤立上传后重跑三槽位 E2E |
| `@音频N` 引用 | parser、插入、重映射和 request snapshot | 用户选择后插入正确官方编号 | 空槽位、`@音频4`、删除已引用项 | 删除调试语法代码后重跑引用测试 |
| 图片模式 | 图片 schema 和互斥测试 | 图片可预览、替换并提交 | 超 10MB、错误格式、图片与音频混用 | 删除临时图片和缓存后重跑图片模式测试 |
| 预设包 | 序列化、checksum、恢复测试 | 一次恢复 Prompt、素材、引用和参数 | 素材缺失、下载失败、checksum 不符、无授权 | 删除失败下载和无引用缓存后重跑恢复测试 |
| 任务/历史/复用 | task snapshot 和历史恢复测试 | 结果可下载，记录能显示并恢复模式和素材 | 临时 URL 过期、本地素材已清理 | 删除测试任务和临时输出后重跑历史测试 |
| 最终清理 | unused、diff、测试和构建检查 | 只保留正式代码、测试和必要文档 | 功能依赖临时文件或本机绝对路径 | 完整测试和宽/窄屏浏览器验收再次通过 |

### 13.6 产物与冗余管理

#### 必须长期保留

- 正式源代码和必要配置
- 能防止回归的自动化测试
- 本执行文档和脱敏后的真实 API 结论
- 明确授权且被预设清单引用的素材
- 正式数据库迁移或兼容代码，并有对应测试

#### 默认不保留

- 搜索和调研下载的原始 HTML、PDF 副本及抓取缓存
- API 原始 JSON、Base64 音频或图片
- 临时生成音频、临时图片、裁剪中间文件和波形缓存
- 调试日志、请求 dump、浏览器临时截图
- `.bak`、`.orig`、`copy`、`draft`、`tmp` 等副本
- 只为一次迁移或排查创建且已经失去用途的脚本
- 已被正式组件替代的旧实现、未引用样式和 feature flag

#### 临时目录规则

- 测试和一次性云端验证统一使用受控临时目录，例如 `/tmp/voice-studio-seed-audio/<run-id>`
- 测试 DB、输出和媒体不得混入用户真实 `~/VoiceStudio` 数据目录
- 真实云端 smoke 输出先下载到测试目录，验证文件大小、格式、时长和可播放性后默认删除
- 如果用户明确要求保留样本，再移动到用户指定位置，并记录用途
- 临时目录必须由创建它的测试或阶段清理逻辑负责删除

#### 阶段清理流程

每个阶段结束按以下顺序执行：

1. 列出本阶段新增和修改文件。
2. 列出本阶段创建的临时目录、媒体、缓存和日志。
3. 用引用搜索和测试确认哪些文件已无消费者。
4. 只删除本阶段创建且确认无用的内容；不得根据文件名猜测并删除用户文件。
5. 检查重复 client、重复 schema、复制组件、未引用 import、死分支和临时 feature flag。
6. 检查是否有 Key、Base64、临时 URL、本机绝对路径或用户素材进入 diff。
7. 运行 `git diff --check`、目标测试和构建。
8. 再做一次真实功能 smoke，确认清理没有破坏功能。
9. 用 `git status --short` 分开汇报本阶段改动和既有工作区改动。

兼容代码只有在仍被旧模型或历史数据真实使用时才能保留，并必须写清楚删除条件。不能为了“看起来干净”删除仍然有消费者的兼容路径，也不能以“以后可能有用”为理由长期保留无测试、无引用的冗余代码。

## 14. 安全、隐私和成本

- 云端生成前必须明确提示 Prompt 和参考素材将上传火山引擎
- 用户可以在设置中控制是否每次确认上传
- API Key 只保存在现有秘密存储机制中，不回显
- 日志不得记录完整 Base64、API Key 和用户隐私素材
- 记录请求 ID 和 Logid 用于排障
- 音色库素材必须检查 `license_status`
- 无授权、未知授权或仅测试素材必须按现有政策限制生产使用
- 页面费用只能显示估算值
- 重试云端请求必须有幂等或重复扣费保护；无法确认云端状态时，不自动重放
- Key 或额度失败时只允许延期真实云端门禁，不允许跳过本地、mock、契约、浏览器和回归测试

## 15. 参数归属规范

以后新增任何参数必须明确归属：

- `common`：真正所有模型共同使用
- `engine`：只属于一个模型
- `mode`：只属于某模型的指定模式
- `postprocess`：模型生成后的统一处理

示例：

```text
seed-audio-1.0 / all / sample_rate
seed-audio-1.0 / audio / references
seed-audio-1.0 / audio / prompt_reference_syntax
seed-audio-1.0 / image / image_reference
indextts-v2 / all / emo_alpha
common / history / save_result
```

“控件位置相同”不等于“参数是所有模型通用”。输出格式就是典型例子：可以使用同一个公共组件，但每个模型的可选值由自己的 manifest 决定。
