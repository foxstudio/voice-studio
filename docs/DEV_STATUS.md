### 开源安全

仓库内无硬编码密钥、无本机绝对路径、无私人联系方式、无数据库或模型权重；运行时数据目录不在仓库路径下。安全检查的做法见下方「验证手法」。

私人素材脚本（音色导入、游戏语音整理等）不进仓库：它们硬编码了本人目录和特定作品信息，对外部使用者没有价值。当前已在 `.gitignore` 登记 `scripts/genshin_*.py`、`analyze_genshin_pack.py`、`voice_importer.py` 等一批路径；新增同类脚本时同一步登记，不要靠事后清理。文件门禁只检查当前受跟踪文件，删除不会清除历史提交里的内容——历史里已经有的私人脚本按“保留原开发仓库”处理，不重写已推送历史。

## 关键经验

### 删页面前先分清“界面”和“能力”

删一个页面之前，先查它的后端接口还有谁在用。转写页删掉后，转写能力仍被音色库的批量 ASR 和语音合成页调用，项目接口仍与视频本土化共享——所以只能删前端路由和侧边栏入口，后端一行不动。删除前还要全局找指向它的链接，以及读它源码的测试（本项目就有一个测试直接 `readFileSync` 页面文件）。

删接口同理：一个路由文件里可能混着有用的和没用的两半。评测路由就是如此，删掉没人读的评测材料端点，保留语音合成页校对动作仍在调用的那个。

### 靠静态扫描删“孤儿方法”不可靠，不建议做

前端 API 层有几十个方法当前没人调用，但**不要批量删**：

- 视频本土化的多个 controller 把 `Api` 作为 transport 的**默认参数**（`constructor(private readonly transport: X = Api)`）。这些方法虽然当前由专用客户端注入、没人直接调，但它们是 controller 契约的实现，删了会让“省略参数直接 new”的写法在运行时崩。
- 搜索时要忽略大小写：`grep -i`。曾因搜小写 `verifyTtsOutput` 漏掉实际叫 `verifyTTSOutput` 的调用，差点误删语音合成页的校对功能。
- 用正则或 AST 批量删属性两次都出了错（括号匹错、吃掉字符）。真要做只能一次删一个并立即编译验证，而收益仅是几十行薄封装，不值当。

### 页面形态可以不同，不必强行统一

视频本土化是工具型工作台（视频预览 + 时间轴 + 任务面板），其余页面是列表型管理页。它的顶部显示当前项目名而非页面标题，也没有搜索框——这些是用途决定的，不是不一致。判断框架是否统一时，先区分“同一控件的两种实现”与“不同用途的两种布局”。

### 前端

- **不要用浮点数做哈希混合。** `seed * 2654435761 + hash` 会超过双精度上限（2^53），低位被吞掉，随机排序退化成固定顺序。用 `Math.imul` 配合异或做 32 位整数运算。
- **同一元素只留一份实现。** 搜索框曾被四个页面各写一遍，值已经漂移（间距 6/8px、圆角 6/7px、高度 28/30/32/34px）。统一的做法是提到 `app.css`，差异用修饰符表达（如 `.compact`）。
- **组件内联样式有作用域隔离，`@import` 的样式没有。** 实测：内联规则编译后带 `.svelte-xxxxxx` 后缀，而 `<style>@import './+page.css';</style>` 引入的类名是裸的、全局生效，且不会触发未使用样式警告。三种写法里 `<style src="...">` 在 Svelte 5 无效（样式会被丢弃）。因此拆样式到独立文件是可接受的权衡（避免主文件过长），但必须先接受失去隔离，并在命名上自律。
- **模板里挂着的类名未必有样式。** 用脚本比对「模板出现的 class」与「CSS 定义的 class」可以一次找出全部死类名，比逐个 grep 可靠。静态 `class="..."` 与动态 `class:xxx={...}` 需要分别扫。
- **改一个接口的返回结构，必须同步改所有调用方。** 把 `/asr/history` 从数组改成 `{items, total}` 后，前端仍按数组直接赋值，结果页面报「filter is not a function」，而且报错位置落在全局布局上，第一眼看不出是哪个页面的问题。改结构前先 `grep` 调用点，改完再全局扫一遍。
- **转写的源音频有两个受管来源**：直接上传的在 `cache/asr_uploads/`，来自音色库、参考音频的在 `assets/reference-audio/custom/`。做路径白名单时两个都要放行，否则一部分记录明明有音频却读不出来。另外 API 出于安全**不返回** `source_audio_path`，需要真实路径时查数据库，不要指望响应体里有。

### 验证手法

- **要验证会写用户数据的操作时，用 Playwright 路由拦截返回假响应。** 请求、成功回调、界面更新都会真实走一遍，但数据不会被改动。批量删除、批量 ASR、单个情绪识别都用这个方法验过。
- **拦截请求还能区分新旧代码是否生效。** 例如「删除一个不存在的文件」在修复前会弹窗、修复后直接放行，行为差异本身就是证据。
- **需要真实模型的链路直接跑本地引擎验证**（用户已授权）。验证字幕跟随播放时，就用库里真实的多段转写记录：点某句 → 确认播放位置跳过去、高亮推进、当前句始终在可视区。
- **浏览器自动化优先用项目自带的 Playwright 起独立实例**（`npx playwright`，系统 Chrome 通过 `channel: 'chrome'`）。`ego-browser` 是与人共用同一个浏览器，一旦有人在窗口里操作，自动化就会被暂停。

### 情绪识别（SER）：复用引擎运行时，不要装进主环境

音色库和语音合成的情绪识别由 `services/ser_service.py` 提供，模型是 emotion2vec+，权重在受管模型目录
`models/emotion2vec-plus-large`（约 1.8 GB，ModelScope 国内直连下载，不走国际源）。三条经验：

- **复用 CAM++ 的 funasr 运行时，不要另建一套。** emotion2vec 与 CAM++ 同属 funasr 框架，
  `ser_service.runtime_root()` 直接复用 `engines/campplus-speaker-verifier`。两者共用一个虚拟环境，
  升级、移动或重装它必须同时回归说话人复核和情绪识别。主环境**不要**装 funasr：torch 会污染主进程。
- **推理必须走子进程。** `ser_worker.py` 一次接收多个音频、只加载一次模型，批量识别因此只加载一次，
  而不是每个音色重启一次模型；主进程只做标签映射这类纯函数。
- **模型返回的标签是「中文/英文」格式。** 实测返回 `生气/angry`、`开心/happy`，映射前必须取最后一段英文名；
  `<unk>` 这类特殊 token 要丢弃，不能归到「平静」。按纯英文键查表会把正确识别出的情绪静默降级成平静，
  而且健康检查依旧显示正常，只能靠真实推理发现。

模型、运行环境任一不完整时，接口返回 503 `SER_UNAVAILABLE` 和可读原因；用真实音频跑一次是唯一能
同时验证 funasr 加载、标签格式和子进程协议的方法。

### 存储保留策略：删除一律走系统废纸篓

设置页「文件与存储」下的「自动清理」管理三类过程产物，天数存在
`storage_retention_cache_days` / `_artifact_days` / `_output_days`，`0` 表示永不清理，
默认是 30 / 30 / 0。三条经验：

- **所有清理都走系统废纸篓。** `services/trash_bin.py` 调 `/usr/bin/trash`（macOS 自带），
  不做不可恢复的删除。移入失败时保留数据库记录并报告原因，避免“记录没了但文件还在”；
  废纸篓不可用时整批跳过，不静默改成直接删。
- **生成结果默认永不清理。** 删了历史里就播不了，要清必须用户自己改策略；
  `outputs/diagnostics` 有自己的清理入口，不参与保留策略。
- **删了要能恢复，测试要真跑一遍。** `tests/test_trash_bin.py` 里有真实的废纸篓往返
  （移入→确认在废纸篓→恢复→比对哈希）；其余清理测试一律用假废纸篓，
  不往系统废纸篓里塞测试垃圾。

### 本机工具

- **改完后端必须重启服务**（uvicorn 未开 `--reload`），而且必须确认旧进程真的退了：旧进程占着 `voice_studio.db.backend.lock`，新实例会直接启动失败退出，端口上继续响应的还是旧代码。重启判断以“文件修改时间晚于进程启动时间”为准，不能只看 curl 通不通。
- 启动后端要带上正式服务同款环境变量（`VOICE_STUDIO_DATA_DIR`、`VOICE_STUDIO_BACKEND_PORT`、`VOICE_STUDIO_VIDEO_LOCALIZATION_WORKER_MODE`），否则会连到另一个数据目录。
- `~/.pi/agent/extensions/safety-gate.ts` 会把危险的 `rm` 改道为移入废纸篓。它曾经把命令里的 `2>/dev/null` 当成删除目标，导致弹窗后报「找不到目标」；现在重定向会被过滤，且目标全部不存在时不再打扰。注意它拦的是**整条命令**：一条命令里只要有一个危险删除，前面的测试、构建也不会执行。
- 该扩展目录已用 git 管理。改动扩展后应在该目录提交，不要再手工留备份。

## 协作偏好

- **说人话**：先给结论，再讲原因。用户不熟悉的术语要顺手解释，配一个具体场景（谁在什么页面做什么 → 系统怎么处理 → 最后看到什么）。不重要的内容一句话带过，不要所有事都展开。
- **给判断，不甩选项**：有明确推荐就直接说，附上理由和影响。
- **改动要能验证**：不能只说「已改好」，要说清验证了什么、还有什么没验。
- **减少重复**：相同元素用一段代码加参数，不要每个页面各写一套。框架统一优先于局部微调。
- **开源视角**：任何改动都要考虑会不会把私人内容、本机路径或临时产物带进仓库。
- 用户会逐页推进，一页做完验收后再进入下一页；发现新分支时先问一个最关键的问题。
