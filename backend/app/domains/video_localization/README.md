# Video Localization Domain

This package owns the backend business rules for source-video transcription and Chinese subtitle/dubbing localization.

## Layers

- `dubbing_completion.read_current_completion` collects the same duration and audio-identity evidence for production completion and readiness. Current accepted/deferred group dispositions supersede historical failures in the problem list without deleting those failures; an explicit new take remains pending. Terminal reconciliation reuses adoption's sibling-placement closeout, limited during replay to earlier workflows so an older formal result cannot cancel a later user request. Neither reconciliation nor completion changes timeline audio or claims subjective listening.

- Generation-plan text pressure and estimated speech duration guide partitioning but are advisory when no safe split exists (`GENERATION_GROUP_CAPACITY_ESTIMATE`). They do not prove that actual audio cannot fit and must not force source-text edits before a take exists. Unknown speech eligibility and mixed speakers remain blocking; candidate-time measured capacity and timeline non-overlap remain enforced by the existing recovery and adoption boundaries.
- `binding_repair.py` owns bounded redistribution of existing source words between consecutive localized subtitles. `service.apply_localized_binding_repair`, exposed by `POST /localized-bindings/repair`, checks the project revision, transcription identity, actual vocals fingerprint and active work before one content save. Chinese text and subtitle/spoken identities are retained; source cue links and affected timing edges are derived from the existing words. Missing, duplicated, reordered or already-generated dependencies reject the entire command. Typed `source_binding_repairs` receipts are server-owned and default to an empty list for older projects; full-Draft saves cannot forge or erase them. This entry does not approve content quality or rebind old acoustic evidence.
- `asr_source_repair.py` owns the deletion-only transformation for independently evidenced bad ASR segments. `service.apply_asr_source_repair` is the sole writer behind `POST /transcription/source-repairs`: it checks Project CAS, current vocals bytes, transcription identity and active tasks, then saves word/cue changes with one typed before-image receipt. Mixed cues retain their IDs; existing Chinese text, timing and word links are protected, and dependencies that cannot safely survive exclusion reject the whole command. Replaying an identical request returns the persisted result without another write; reusing its ID with different input or replaying after a later transcription edit fails closed. This is a bounded correction, not a new ASR pipeline or permission to rebind old quality approval.
- Acoustic ASR spelling hints come only from the explicit glossary via `transcription.automatic_asr_context_terms`; filenames and bracketed media identifiers remain research metadata, not decoder vocabulary. Qwen's shared audio chunker keeps a final remainder within its boundary-search budget attached to the preceding chunk, preserving all frames instead of independently decoding a tiny tail. Neither boundary filters recognized text by matching prompt words.
- `dubbing_text_rebase.py`: the save boundary preserves reviewed group identities for text-only localized edits with unchanged membership, timing and source contracts. It advances editorial lineage and calls the shared `dubbing_plan_continuation` checks for local dependencies, audio bytes and retained projection; display-only changes with unchanged spoken text do not invalidate acoustic proof; changed groups keep their media but lose current pass claims. Frozen tasks, user deletions, clip timing/crops and display-versus-spoken wording remain independent. Structural edits retain the ordinary replanning path; an unallocated spoken edit spanning multiple reviewed units does not guess a new allocation.
- `dubbing_generation_identity.py`: generation history, current inspection evidence and actual timeline placement have separate authorities. The production read model and executor use one frozen-request matcher, exposed through the application port, to find successful unplaced results after a replan. Such a result is pending local inspection, not a fresh generation slot or a quality pass. Historical workflow parameters remain immutable; cancelled/discarded results are excluded, and media/placement validation remains with the existing shared finisher. No extra persisted total-status field is introduced.
- `asr_uncertainty.py`: shared pure projection of unresolved transcript evidence onto aligned word IDs, used by subtitle segmentation and localization source locking. New review decisions persist versioned `AsrUnconfirmedTextSpan` records separately from proposed edits; absent legacy fields remain absent on serialization. The read-only legacy adapter accepts only complete saved diagnostics. Located evidence emits `asr_unresolved_text`; missing, stale or ambiguous scope emits `asr_unresolved_scope_unknown`, never a false verification or an assertion that a whole segment is incorrect. Source locking changes only these projected flags, not the saved transcript, cue text or timing.
- `service.py`: application/domain facade for project media, ASR, localization, subtitles and TTS use cases. It checks project existence, loads drafts, and delegates to focused domain modules; it does not import or submit back into the operation queue.
- Formal ASR and localization use an injected pure finalization projection at their content-save boundary. The queue owns task-summary/terminal semantics; the service owns source or localized tracks. One existing Project transaction commits both the tracks and operation success, including ledger/read projections. Post-commit observer failures cannot turn persisted success into failure; cancellation, execution fencing and concurrent source/target edits still reject before publication. This does not mark advisory content warnings as human approval.
- `workflow_submission.py` owns the versioned, secret-free identity captured for newly submitted formal ASR and localization tasks. It reuses source, provider and workflow behavior fingerprints; queued input/configuration drift rejects before model work. Source snapshots are built from the verified Draft read, while UI/editor state remains independent. Legacy operations without this binding retain read/execution compatibility without acquiring fabricated submission evidence.
- History placement recovers a matching submission's frozen multi-subtitle/source binding rather than narrowing it to the primary subtitle. Same-result explicit replacement can repair that binding without replacing other takes.
- Retained-content evidence includes the first playable razor slice even when descendants reference its media identity; an overlapping resurfaced source remains excluded. Slice numbering and alignment labels do not change retained-audio evidence identity. Verified retained cuts are not expanded by automatic gap restoration; word coverage, actual timing and atomic-save checks still apply.
- Timeline markers are project-owned Draft content. User CRUD and idempotent automation markers both pass through `service.py`; the dubbing application facade may create a continuation marker only after verifying a current candidate report and exact main-lane group coverage. Markers remain annotations, while production state is still projected from the plan, candidate evidence, timeline clips and current marker lineage.
- `app.services.video_localization_operations`: the transport-facing operation application port. API routes use it for submit/list/detail/cancel/retry and restricted development-result reads. It owns the shared draft-write lock around submission and delegates lifecycle execution to `operation_queue.py`, keeping the dependency direction `API → application port → queue → service/domain`.
- `draft_store.py`: project-parameter persistence for the `video_localization` draft plus quality-gate refresh before save/export. `get()` is a query: it may normalize a returned projection in memory, but never writes the database or snapshot, migrates directories, or silently restores snapshot state. `repair()` is the explicit command for legacy-directory migration, managed-path rebasing, normalization persistence, and snapshot recovery. Repeating a repair with the same semantic quality result preserves the prior check timestamp and does not create another autosave merely because wall-clock time advanced. It owns the shared draft write lock used to prevent an export commit from overwriting a concurrent edit.
- `project_snapshot_projection.py` and `app.services.video_localization_project_snapshot_store`: recoverable projection from the authoritative Project row to `project.json`/autosave. Project CAS and one coalesced pending revision commit in the same SQLite transaction; post-commit file failure is recorded and retried on a later foreground snapshot write or bounded startup replay. The writer serializes each project across threads/processes, reloads the latest Project under that lock, writes JSON with fsync + atomic replace, and conditionally clears only the revision it covered. Content and explicit repair requests autosave and refresh the mirror before returning; high-frequency runtime/workspace writes only coalesce the pending primary-snapshot revision so TTS placement is not blocked by rewriting the complete project package.
- `project_lifecycle_cleanup.py` and `app.services.video_localization_project_cleanup_store`: post-commit reset/delete saga. The SQLite commit atomically records the cleanup job/tombstone with Project/operation and delete-owned task/history/batch changes. A delete command returns after that commit and queues the durable job on one process-local serial worker; startup enqueues a bounded pending batch without running cleanup inline. The worker atomically stages the stable project package under `.trash`, reprojects an empty reset snapshot, removes caches and unreferenced secondary artifacts, and purges staging. Failures remain replayable; delete tombstones block package reconcile and pending reset cleanup blocks new Draft writes.
- `app.services.durable_files`: the shared fsync + atomic-replace primitive used by project snapshots, package staging, and managed operation artifacts.
- `operation_elapsed.py`: the shared pure elapsed-time helper for operation detail projections. Current timezone-aware timestamps are normalized to UTC, while legacy timezone-naive values retain the established UTC interpretation, so mixed historical rows cannot crash task detail reads.
- `schemas.py`: domain schema facade. It re-exports the current stable Pydantic models so domain code has one import boundary while preserving class identity.
- `source_pipeline.py`: atomic source media import, source-audio extraction, stem separation, and source-language ASR draft generation. New separation always uses the managed BS-RoFormer Viperx-1297 provider; it estimates vocals only and derives background as the sample-aligned residual `original mix - vocals`. Source ASR `auto` requires the managed vocals stem, and transcription, diarization, alignment, and acoustic review keep that same vocals identity; missing vocals block for separation instead of silently falling back to the original mix. The explicit `original` request remains available only for a caller that deliberately selected it. Prepared contexts fingerprint the actual source bytes before inference and keep temporary dub paths runtime-only. Replacing source media invalidates the detected language together with the old transcription. Upload streaming stays async and the blocking media probe runs in a worker thread.
- Cue timing confirmation is either `auditioned` or `asr_vad_verified`. The latter records the current transcription revision, separated-vocals track hash, exact cue word IDs, and either current boundary references or one persisted source-timing correction with its raw VAD range. The public batch correction command is CAS-bound to the project revision, source text/word ownership and live vocals hash; it atomically updates only verified word times, affected display anchors and cue ranges, and preserves any superseded diarization span as history rather than treating it as a new timing measurement. Point anchors remain low-confidence and cannot turn a cue blue. Both confirmation methods set the same derived verified state; warnings stay advisory when evidence is absent or stale.
- `asr_pipeline.py`: the single execution facade for raw ASR, non-fatal automatic speaker diarization and its explicit join, document understanding, iterative research evidence, transcript review, and the complete ASR workflow. Formal ASR v2 publishes raw ASR and anonymous-speaker analysis as parallel durable tasks followed by their join. VibeVoice providers compute both branch results in one shared inference and project them into the existing versioned artifacts; Qwen and other text-only providers keep the independent MOSS path. A usable multi-voice result adds anonymous ownership; a single stable voice adds no redundant label, and an unavailable or failed speaker model leaves the main transcript usable with one task-level warning instead of marking every cue. Explicit development breakpoints and standalone speaker analysis call the same atomic methods. Document-understanding contracts are imported only from their canonical data module. Document understanding deterministically adds bounded search-and-frame checks for unplanned mid-sentence capitalized names and isolated non-Latin dialogue in an otherwise Latin-script film transcript; the latter asks visual evidence to transcribe the source movie's visible subtitle exactly and never treats an audio translation as visual evidence. If a paid transcript-review result becomes unknown, the workflow never replays or applies that uncertain result: it keeps the unchanged raw ASR plus explicit glossary edits, runs the same local transcript quality gate in advisory mode, and continues alignment only when the local text/timing invariants pass.
- `asr_targeted_relisten.py`: bounded acoustic evidence for the single decision pass. It ranks only the sparse issues that genuinely need confirmation, crops their exact short-audio ranges, reuses the active ASR engine and a small set of spelling hints, and returns at most twelve candidates. The decision task compares those candidates with the current text; no extra whole-document review is added.
- `document_understanding_contracts.py`: data-only, versioned input, result, brief, candidate, section, timing, quality, and raw-response models for document understanding. Atomic research, visual, section-review, and whole-recheck modules import this boundary directly instead of importing the ASR execution facade.
- `asr_document_understanding_execution.py` and `asr_document_understanding_provider_gateway.py`: the managed `understand_document` application boundary. Submission locks the managed initial-analysis lineage, scene context, profile configuration and behavior fingerprint; execution reuses `AsrPipeline.run_document_understanding()` through a typed per-call gateway instead of copying the full-document/window/final-normalization algorithm. Each logical model attempt has a durable Provider step and privacy-safe artifact; paid unknown results fail closed and block retry under a new operation ID.
- `asr_document_understanding_result_reader.py`, `asr_document_understanding_detail_reader.py` and `asr_document_understanding_operation_projection.py`: same-snapshot result/detail assembly and the single public summary projection for managed document understanding. The readers verify prepared input, dynamic call manifest, call artifacts and deterministic final output without opening Project JSON or desktop development snapshots.
- `visual_evidence.py`: provider-neutral bounded frame-evidence algorithm. It consumes visual questions from document understanding, moves special-language subtitle checks ahead of lower-value visual questions, narrows an overly broad subtitle question to the actual non-Latin dialogue, and scans bounded points inside that dialogue range. It checks one likely evidence frame first, adds a second bounded round with only new frames when needed, and returns only directly visible observations and candidate-bound search clues. Frame extraction and multimodal completion enter through typed gateways, so this module neither owns operation lifecycle nor persists runtime paths.
- `asr_visual_evidence_execution.py`, `asr_visual_evidence_extraction_gateway.py`, and `asr_visual_evidence_provider_gateway.py`: the managed `visual_evidence` application boundary. Submission locks the managed document-understanding final artifact, current video SHA-256/duration/frame rate, frame policy, resolved non-secret model configuration, and behavior fingerprint. Local extraction commits hash-verified JPEG artifacts before each typed Provider call; a paid unknown result fails closed and blocks retry under a new operation ID. A final local step references only committed frame, extraction-manifest, and successful call artifact fingerprints.
- `asr_visual_evidence_result_reader.py`, `asr_visual_evidence_detail_reader.py`, and `asr_visual_evidence_operation_projection.py`: same-snapshot result/detail assembly and the single public summary/step projection for managed visual evidence. They validate the full lineage plus JPEG bytes without reading Project JSON or legacy desktop snapshots. Restricted frame reads resolve the same managed authority, revalidate the artifact hash, and expose only the requested operation-owned file.
- `research_evidence.py`: versioned, bounded research orchestration. It searches only candidates produced by document understanding, asks the configured LLM whether evidence is sufficient after each round, records why it stopped, and never decides canonical names or edits transcript text.
- `asr_research_evidence_execution.py`, `asr_research_evidence_search_gateway.py`, and `asr_research_evidence_provider_gateway.py`: the managed `research` application boundary. Submission locks managed document/optional visual final artifacts, bounded policy, non-secret LLM/search configurations, and the behavior fingerprint. Every real search, query rewrite, and evidence assessment is a typed durable Provider step; Tavily uncertainty fails closed as `result_unknown`, while free-search retries use distinct stable attempts. Execution replays committed calls before a deterministic final manifest and never reads the legacy seven-day cache.
- `asr_research_evidence_result_reader.py`, `asr_research_evidence_detail_reader.py`, and `asr_research_evidence_operation_projection.py`: same-snapshot managed research authority and the single public summary projection. The readers validate prepared/final local steps, every referenced search/LLM artifact, candidate coverage, budgets, evidence provenance, and final fingerprints without opening Project JSON or desktop snapshots. Empty-candidate research completes with two local steps and zero external calls.
- `asr_entity_normalization_execution.py` and `asr_entity_normalization_provider_gateway.py`: the managed `normalize_entities` application boundary. Submission accepts only a successful managed research result, locks its final artifact plus the complete current glossary, actual non-secret profile configuration and behavior fingerprint, then executes glossary rules locally and persists each necessary canonical-name/variant model attempt as an independent Provider step.
- `asr_entity_normalization_result_reader.py`, `asr_entity_normalization_detail_reader.py`, and `asr_entity_normalization_operation_projection.py`: same-snapshot entity-normalization authority. They rebuild the exact research/glossary request, validate transcript identity, evidence/change safety and the complete call manifest, and never reread the mutable Draft glossary or legacy desktop snapshot for a new managed task. Empty-evidence and glossary-only runs use two local steps and zero model calls.
- `asr_section_review_execution.py` and `asr_section_review_provider_gateway.py`: the managed `section_review_r1` application boundary. Submission locks successful managed entity-normalization and document-understanding final artifacts plus their shared lineage, the resolved non-secret profile configuration and the review behavior fingerprint. Each section/attempt is an independent Provider step, so parallel execution can reuse committed sections after interruption; known section failures remain typed partial results and an unknown paid result blocks replay.
- `asr_section_review_result_reader.py`, `asr_section_review_detail_reader.py`, and `asr_section_review_operation_projection.py`: same-snapshot section-review authority and the single public summary projection. They rebuild the exact two-upstream request, validate every successful or known-failed Provider step, call artifact, section run, issue target, evidence reference and quality metric, and never reread the mutable Draft glossary or a legacy desktop snapshot for a new managed task.
- `asr_review_decisions_execution.py` and `asr_review_decisions_provider_gateway.py`: the managed `review_decisions_r1` application boundary. Submission accepts only a successful managed section-review authority, locks its final artifact, behavior identity and—only when issues exist—the actual non-secret model configuration. Primary judgment, structured-output retries and the missing-issue coverage call are separate durable Provider attempts; the coverage input references the committed primary artifact, and an unknown paid result blocks replay.
- `asr_review_decisions_result_reader.py`, `asr_review_decisions_detail_reader.py`, and `asr_review_decisions_operation_projection.py`: same-snapshot review-decisions authority and its public summary projection. They rebuild the exact section-review request, validate the complete attempt/artifact lineage plus transcript and edit-safety invariants, and keep running preview transient. Empty-issue runs use only prepare/final local steps and never resolve or call a model.
- `asr_whole_recheck_execution.py`: the managed `whole_recheck_r1` application boundary. Submission locks successful managed review-decisions and document-understanding final artifacts plus their shared lineage, resolved non-secret profile configuration, review round and behavior fingerprint. Execution is deterministic and local; historical Provider-attempt artifacts remain readable but no new Provider step is created.
- `asr_whole_recheck_result_reader.py`, `asr_whole_recheck_detail_reader.py`, and `asr_whole_recheck_operation_projection.py`: same-snapshot whole-recheck authority and its public summary projection. They rebuild both upstream requests, validate the complete attempt/artifact lineage and read-only transcript invariants, and never fall back to mutable Draft state or legacy desktop snapshots for managed operations.
- `asr_transcript_quality_gate_execution.py`: the managed `transcript_quality_gate` application boundary. Submission locks one successful managed whole-recheck final artifact and the deterministic rule fingerprint. Execution rebuilds the request only from that authority, then commits prepare/final `local_free` steps under the execution fence; it never reads current Draft/media state and has no Provider step.
- `asr_transcript_quality_gate_result_reader.py`, `asr_transcript_quality_gate_detail_reader.py`, and `asr_transcript_quality_gate_operation_projection.py`: same-snapshot quality-gate authority and the single public summary projection. They revalidate the locked whole-recheck lineage, canonical local artifacts and exact deterministic result, keep public payloads path-free, and fail repair-required instead of consulting current media or a legacy desktop snapshot.
- `visual_name_evidence.py`: pure, deterministic projection from candidate-bound visual hints to exact name claims. A claim must link one transcript variant to one complete screen spelling, real source segments and saved frame IDs; ambiguous, unrelated, numeric or low-confidence text is rejected before the model sees it.
- `entity_normalization.py`: versioned, evidence-backed name and terminology normalization. It applies project glossary locks, consumes both web evidence and typed visual name claims, reuses the proven canonical-name checks, and returns complete updated transcript segments plus explicit changes and warnings. A one-off phonetic candidate cannot become a separate canonical entity merely because search found a similarly named wrapper site when the transcript repeatedly and more confidently names the main product; direct visual evidence or repeated unambiguous context still preserves genuinely separate tools. When the mapping model omits one singleton candidate, a local fallback may attach it only to one uniquely matching, repeatedly mentioned canonical name, using stricter version and proper-name safety checks.
- `entity_normalization_runtime.py`: composition adapter for the canonical-name algorithm in the current ASR review module. `entity_normalization.py` owns the atomic service and typed contract without statically importing the workflow facade.
- `section_review.py`: versioned, read-only transcript issue discovery. The single current round checks the complete immutable document plan. Model input uses compact segment text plus only the evidence fields needed for judgment, while output remains a minimal typed issue list so edits can still be located and validated deterministically. Shared local text rules seed grounded repetition, redundant-phrase and suspicious-capitalization candidates.
- `transcript_text_rules.py`: conservative, deterministic ASR text rules. It normalizes only safe currency, percent, punctuation and whitespace display details; lexical anomalies become grounded review candidates and are never blindly applied. A repeated, determiner-bound phonetic term outlier is routed to model adjudication with its dominant transcript variant, but frequency alone never edits text.
- `transcript_boundary_issues.py`: conservative, deterministic discovery of high-confidence issues that cross two adjacent ASR segments, such as a question boundary before a connector or a decimal split at the segment boundary. It emits grounded patch sets but never applies them.
- `review_decisions.py`: versioned review adjudication and deterministic edit application. The model may only decide issues supplied by `section_review`; local rules enforce confidence, unique matching, number/negation preservation, evidence-backed names, and monotonic locked changes before complete transcript snapshots are published. After those decisions, the same task applies the shared non-lexical orthography normalizer, including when there are no model issues, without making an extra model call.
- `whole_recheck.py`: versioned, local, read-only closure after the single review-decision pass. It verifies decision coverage, known references and deterministic transcript-boundary findings, then either finishes or stops with exact manual-review locations. It never calls a model or edits transcript text or timing.
- `transcript_quality_gate.py`: deterministic, versioned readiness gate between the final whole recheck and word alignment. It never calls a model or edits the transcript; low-confidence wording becomes a non-blocking replay advisory, while failed upstream state, an unfinished automatic review round, or broken invariants still block alignment.
- `review_contracts.py`: data-only contracts shared across transcript review stages. It keeps accepted-change locks and their provenance independent from atomic implementations, preventing review modules from importing one another in a cycle.
- `review_warning_policy.py`: deterministic reader/debug projection policy shared by the ASR orchestrator and current section-review API. Rejected, unlocatable model suggestions remain in debug data without creating reader-facing warnings; the policy module imports no workflow implementation.
- `web_research.py`: search-provider adapter, cache, transient retry, safe-query gate, Wikipedia/general-web fallback, and source relevance filtering.
- `llm_contracts.py`: provider-neutral, data-only model-call record and purpose contracts. It stores purpose, round, model, request size, token usage, cost, duration, reasoning control, finish reason, and errors without importing the LLM runtime.
- `llm_observability.py`: runtime trace collector plus the single reader/debug projection used by formal runs and development breakpoints. Every recorded call projects its actual model ID, provider route, profile ID, usage and stop state; verified zero-call steps remain explicitly model-free. It compatibility-re-exports the contract objects and never persists prompts, model output text, or hidden reasoning.
- `workflow_contracts.py`: versioned parent-stage and atomic-task definitions shared by task summaries, WebUI, OpenAPI, and external agents. Source-audio, stem separation, automatic reference candidates, standalone speaker diarization, every managed ASR development node through transcript quality gate, formal ASR, localization v3, and semantic TTS grouping publish canonical workflow definitions instead of inheriting the generic operation fallback.
- `managed_local_step.py`, `managed_local_detail.py`, and `managed_local_workflow_specs.py`: shared primitives for deterministic `local_free` workflows. The first owns fenced prepare, operation-stable input identity, canonical artifact commit, success replay and terminal failure; the second validates typed parameters plus ledger/step/artifact lifecycle in one query-only snapshot, with a zero-input wrapper for the simpler workflows; the specs bind a workflow identity to its typed codec. They contain no source-media or Project mutation policy.
- `source_audio_execution.py`, `source_audio_operation_projection.py`, and `source_audio_detail_reader.py`: the sole managed `source-audio-workflow-v1` path built on those shared local primitives. Execution owns the source fingerprint and Project media saga; projection owns public initial/success summaries; the detail reader owns source-specific lifecycle wording. The final Project media projection and operation success share one Project save, so artifact or Project commit failure cannot leave a product success with missing detail. `operation-v1` source-audio history remains an explicit legacy adapter.
- `stem_separation_execution.py`, `stem_separation_operation_projection.py`, and `stem_separation_detail_reader.py`: the sole managed `stem-separation-workflow-v1` path. Execution locks the actual source-audio SHA-256, writes two operation-owned media files plus a path-free typed artifact, reuses hash-verified files after a crash, and commits the newest Draft stem projection with operation success in one fenced Project save. Missing media is locally regenerated and must exactly replay the saved output contract; legacy `operation-v1` stems remain read-only compatibility history.
- `reference_candidates_execution.py`, `reference_candidates_operation_projection.py`, and `reference_candidates_detail_reader.py`: the sole managed `reference-candidates-workflow-v1` path for automatic cue-derived candidates. It locks the actual clean-vocals SHA-256 plus the ordered candidate/relevant Draft revision, writes operation-owned clips and a path-free typed media manifest, and merges only reference/cue/speaker state into the newest Draft. Relevant concurrent edits fail closed; unrelated UI/timeline state survives. Manual cue/time selections remain synchronous edit commands and never enter this zero-input workflow.
- `semantic_tts_grouping.py` and `semantic_tts_grouping_execution.py`: the former owns only deterministic item preparation, source fingerprinting, limit normalization, group validation, and result projection. The latter is the sole Provider execution boundary: it pins the resolved non-secret profile configuration, persists each submitted round and typed artifact through the shared Provider lifecycle, and requires an `ExecutionFence`. The service facade performs the final source-fingerprint CAS and Project commit; no second direct-LLM path remains.
- `timeline_timecode.py`: the backend formatter for user-facing media positions and ranges. Internal contracts keep integer milliseconds; task details and model-facing visual prompts use the project frame rate and compact Chinese hour/minute/second/frame labels.
- `speaker_diarization.py`: runtime audio-only speaker input/output contracts, speaker-count quality guidance, and hash-checked attachment to ASR segments. `speaker_diarization_execution.py` prepares one fenced local-free step from the actual audio SHA-256 and canonical parameters, stores `speaker-diarization-step-output-v1` without `audio_path`, and replays a committed result without rerunning inference. `speaker_diarization_detail_reader.py` and `speaker_diarization_operation_projection.py` assemble product detail and summaries from the managed authority while leaving the formal Draft untouched.
- `asr_raw_execution.py`: managed execution for the raw-ASR development breakpoint. The raw result contract is `asr-raw-v2`: it records the resolved track, actual audio SHA-256, and at most eight automatically selected spelling hints from the project glossary and bracketed source filename text. Qwen receives those hints as one short plain-text system prompt; engines without hint support ignore them. The prompt is advisory and cannot force words absent from the audio. For long mixed-language input, an empty automatic-language chunk gets one English recovery attempt; generation is bounded per chunk and an output that exceeds a conservative human-speech character rate is rejected as an explicit incomplete range instead of persisting a decoder repetition loop. The managed artifact stores the complete typed transcript, bounded quality/timing metadata and no runtime path.
- Formal ASR defaults to automatic speaker analysis; an explicit null skips it. Audio longer than fifteen minutes is analyzed in bounded windows with two seconds of read-only context, midpoint ownership removes boundary duplicates, and source speaker labels are namespaced per window before CAM++ performs cross-window consolidation. The join applies anonymous speaker labels only when at least two stable acoustic clusters survive quality checks. A one-cluster result remains useful evidence that the content is acoustically single-speaker, but does not label every subtitle. Temporary windows live outside product data and are deleted with the request lifecycle.
- `asr_initial_analysis_execution.py`, `asr_initial_analysis_detail_reader.py`, and `asr_initial_analysis_operation_projection.py`: the sole managed `asr-initial-analysis-development-workflow-v1` path. One prepared source context resolves and fingerprints the audio once, then prepares raw-ASR and diarization steps before `AsrPipeline` starts both branches in parallel. Raw-ASR failure is fatal; ordinary diarization failure is committed as a typed degraded outcome and becomes a stable warning, while cancellation, fence loss, invalid output, or artifact failure still aborts. The deterministic join artifact references both branch artifact fingerprints and stores only joined segments/warning codes, so it does not duplicate full branch payloads. The same-snapshot reader validates typed core, all three steps, artifact bytes/contracts, shared audio identity and join fingerprints without reading Project JSON; restart replays committed branches and never changes formal transcription/cues.
- `cues.py`: ASR cue creation, cue patch validation, and cue quality flags.
- `speakers.py`: speaker roster creation/update plus cue/reference-derived speaker timeline reconciliation.
- `workflow_ledger.py`: shared progress, timing, reporting, and atomic-result ledger for the sole production localization workflow. The caller must provide the versioned workflow definition explicitly.
- `localization_document_brief.py`, `localization_document_evidence.py`, and `localization_spoken_script.py`: the document-first v3 understanding, bounded evidence, continuous target-language script creation, fidelity review, blind naturalness review, and finalization contracts. A visual question keeps its model-selected cue range as the evidence owner, while frame collection may include one nearby cue on each side as read-only context. Frame timestamps come from the audio cue intervals: every short cue contributes its center, and a long core cue contributes beginning, middle, and ending samples. This lets several fast-changing hard-subtitle lines be read without pretending that a sampled picture proves subtitle timing or turning neighboring footage into a new claim. Finalization gives each currently editable sentence an internal structural target ID and permits only validated replace, insert-before, insert-after, or delete actions, so omitted material can be restored without replacing an unrelated surviving sentence; repeated expression-level findings receive one target ID per exact occurrence, while story-fact findings remain ambiguous instead of guessing. These IDs never enter user-visible subtitles or shared timeline contracts. Creation and mother-tongue finalization use the configured creative profile. A native-sounding document may ignore only low-severity polish; every high- or medium-severity local finding remains actionable. After each targeted correction, validation is limited to the already confirmed issues and the edited sections; it does not reopen the untouched full document, and only unresolved findings may enter one second targeted correction.

Replacing one clip with evidence-backed slices does not invent a new blocker merely because the slice clip ID or the symmetric overlap pair order changed; a genuinely new group relationship, coverage loss, scene overrun, or other blocker still rejects the edit.
- When energy analysis reports several safe-looking gaps between the same two aligned words, automatic editing selects only the strongest gap. The other intervals stay intact and are marked uncertain, preventing a wordless isolated slice or removal of unaligned audio between duplicate acoustic detections.

## Boundary Rules

- Candidate close-out bounds source-rhythm pause expansion by the current group's delivery window. A processed take that still exceeds its target end requires group recovery rather than displacing later speech. Acoustic processing reports do not assert subjective listening approval; their subjective status remains `not_reviewed`.
- A planned split may retain the source clip ID for its first slice. Candidate projection filtering retains these explicit slices while excluding genuinely replaced unsliced source clips.

- Source-audio extraction, stem separation, English ASR, synthesized-dub subtitle reconstruction, and automatic reference-candidate discovery have one public execution lifecycle: submit an operation and read its state/result.
- Reference clips are created only by the managed automatic candidate workflow. The retired manual project-voice library and selection-save commands are not part of the domain API.
- Other blocking media rendering and export work must run through an operation, a synchronous FastAPI worker route, or `asyncio.to_thread`; an `async def` route must not call ffmpeg, ffprobe, Demucs, or another blocking provider directly.
- Keep feature-specific business rules inside this package, not in `backend/app/api`.
- Keep API routes as transport glue: request/response shape, attachment responses, and error mapping only.
- The frontend may initialize an export request from current track visibility, mute, solo, and media availability. Once the user opens the dialog, the typed request is authoritative: manually selected hidden/muted tracks are allowed, and omitted tracks must not enter the mix.
- Keep shared TTS queue behavior in existing shared services. Generic generate,
  task and longform entrypoints coordinate project registration, terminal state
  and result placement only through
  `app.services.video_localization_tts_handoff`; the application composition
  root injects this package's project projection functions. Focused placement
  rules remain in `tts_orchestration.py`/`tts_placement.py`.
- Generate-page handoff uses the side-effect-free TTS preview contract. Direct
  in-page reuse creates a stable submission ID and calls the authoritative
  handoff reserve before reference-media materialization, projects the accepted
  workflow immediately, and then calls prepare plus generic `/generate`. The same ID follows the request through the queue,
  placement, failure, deletion, and refresh projections. Reference preparation,
  submission validation, or queue-registration failure terminalizes and keeps
  that workflow as a deletable task fact; the page must not substitute an
  ephemeral client-only placeholder. A prepared workflow without a generation
  task is treated as an interrupted submission after two minutes and is never
  replayed into a paid provider.
- Candidate CQC freezes the actual submitted TTS text as its transcript target;
  the versioned generation group remains the authority for semantic scope and
  timeline coverage.
- `app.services.video_localization_tts_handoff_store` is the durable,
  versioned handoff outbox for task registration, generated-result placement
  and failed/cancelled longform terminal projection. Registration rows commit
  with their task/longform source row; placement rows commit with history;
  terminal rows commit with the longform task. Delivery is at-least-once and
  project projection is idempotent by task/workflow identity. Startup replays
  a bounded pending batch in a background worker, and abandons poison events
  after five failed automatic attempts so API readiness is not blocked. Each
  runner must first acquire a SQLite-serialized
  60-second lease with a monotonic fencing token; the Project transaction and
  outbox completion both validate that live claim, so an expired or superseded
  runner cannot commit. Project reset abandons pending delivery before the
  empty Draft becomes visible, while project delete removes all handoff rows
  in the same SQLite transaction. Slow projection calls maintain a 10-second
  heartbeat that only extends the same still-live runner/token claim; an
  expired or superseded claim is never revived. Long-term applied-row
  retention remains explicit follow-up work.
- Shared TTS progress persistence is best-effort observability. A transient
  database write failure may delay the displayed percentage but must not abort
  an already running inference subprocess.
- Video-localization history deletion uses the typed
  `POST .../video-localization/tts/history/delete` command. Single-record,
  subtitle-scope, and whole-project UI actions share this boundary; the
  frontend must not issue one generic history DELETE request per row.
- `HistoryItem` keeps the complete immutable generation fact, while `history_metadata` and `history_scopes` are its transactionally maintained query model. Project/source pagination and current-subtitle membership use those indexes; interactive reads never scan every history JSON document.
- Localized subtitle `text` is the final on-screen text and `tts_text` is the final spoken script. Both are independently editable and persist through the same bounded mutation; player overlays and subtitle export consume `text`, while every preview/submit/retry handoff consumes `tts_text` (falling back to `text` only for legacy rows that never stored spoken text). Display text, spoken text and timing form the frozen TTS generation target, but they do not own durable timeline media. A display-only edit with an explicit unchanged `tts_text` retains the current binding. An effective spoken-text/timing edit clears the subtitle's current-result mirror, cancels only unfinished placeholders, and marks already materialized clips with `tts_target_binding_status=stale`; their audio source, clip ID, source range, timeline range and dub lane remain unchanged. Recommitting formal localization tracks follows the same rule. Only an explicit clip/workflow deletion, project/source replacement, or project reset may remove durable timeline media.
- A formal dual-track project may shorten one `localized_spoken_segment.text` through its typed patch endpoint without rewriting the linked display subtitles or source ownership. The edit changes the backend-owned dubbing source revision, so an older generation plan, frozen candidate input, CQC report or timeline audit can no longer authorize new placement; the caller must submit a new current plan before generating again.
- A full client Draft save never treats an omitted timeline clip as a deletion. Its workspace route also never changes an existing clip's track, timeline range, source range, or media source; an explicit `dub_lane` intent remains the one compatible full-save exception. A browser workspace snapshot that both changes an existing source clip and adds a child traced to it is rejected with `VIDEO_LOCALIZATION_TIMELINE_EDIT_REQUIRES_PATCH`: split/crop transactions must use the typed timeline-edit PATCH so the parent precondition and child insertion are atomic. Timeline removal is authorized only by the transient `client_timeline_edit_intent.deleted_timeline_clips` carried by the save packet that owns the edit. Each deletion and bounded edit names both the stable clip ID and the media-generation identity observed by the client; an old command is rejected or ignored when that clip ID now belongs to a replacement generation. A client-created dub child is accepted only when the same packet names it in `added_timeline_clip_ids` and the server can trace it to an existing same-generation source clip; arbitrary empty dub clips and stale deleted children remain rejected. The server consumes and strips the intent. History-result placement rebases its command on the latest Draft inside the shared atomic updater, so UI autosave, task projection, and another browser cannot turn a successful drop into a stale overwrite. Explicitly reapplying a historical result also removes that result's task/generation tombstones in the same atomic write; a later explicitly added split may therefore become durable instead of being mistaken for a late result from a discarded task.
- Browser timeline transactions start their typed timeline-edit save immediately after the edit commits; the longer workspace debounce is reserved for non-structural draft changes. Each compact transaction may carry a stable request ID. Its parameter fingerprint and original bounded public receipt are committed in the same Draft write, so a response-loss retry returns the original result without weakening clip identity/editable-state fences or overwriting later work. Receipts are server-owned, omitted from the workspace, and bounded by recent count plus serialized bytes without a wall-clock TTL. While a result is uncertain, the controller retains the original request ID, payload and checkpoint and confirms that receipt before sending later edits. If that replay receipt is older than a complete snapshot already consumed by the browser, it confirms the checkpoint without applying its old partial payload; the browser refreshes a complete workspace at least as new as its observed revision, removes the confirmed operation from that baseline and replays only later local edits. An explicit 4xx/409 rejection keeps the concrete error and unsaved local edits visible; a newly prepared command may use a new request ID, but still must pass the original identity/version fences and cannot evade a real conflict by changing identity or parameters. Reloading or switching a loaded project first flushes pending work instead of resetting its edit controller. Frontend regression commands isolate both SvelteKit's generated files and the final static distribution in a run-owned `.voice-studio-regression.*` directory that the development server explicitly ignores; browser acceptance serves that same isolated build, so checks and builds cannot rewrite or reload the live editor.
- Bounded timeline commands use the `editorial` write intent; UI-state commands use `workspace`. These commands read the stored Draft without whole-project read repair and commit through the same Project CAS and snapshot outbox, but do not rebase text, normalize unrelated clips, rebuild production state, or run the global quality gate. Editorial saves request an autosave projection without flushing the whole project package before the acknowledgement. Existing quality evidence keeps its original check time; it is not a new audit. Explicit source edits mark existing derived dub captions stale directly. Production/content/repair writers retain their existing preparation and quality checks.
- A validated audio edit sets the backend-owned `timeline_timing_version: editorial-v1` on the affected clip. The shared reader/public timing normalizer preserves that clip's exact milliseconds; unmarked legacy clips retain their compatibility normalization. UI saves cannot acquire or forge this marker. Plain single-subtitle timing commands use the same editorial persistence intent; wording commands retain their existing text-rebase policy.
- `timeline_editor_collections.py` owns field-level optimistic merging for the optional typed `cue_collection_change` and `localized_subtitle_collection_change` expected/desired collections. Only changed editable fields and explicit insertions/deletions are applied to the latest Draft; same-field conflicts abort the entire timeline transaction, while unrelated fields and concurrent rows survive. `dubbing_production` 门面提供只读组时长检查；只用当前计划中同说话人、同引擎、同速度的成功候选估算，缺少证据返回不确定，超时估算只提示，完全没有连续可用窗口才阻断。执行器在预留任务前复用该检查，结果冻结进生成参数。

`POST dubbing/recovery` 接收 `dubbing-recovery-decision-v1`：当前来源及计划版本、稳定恢复 ID、组、明确分句、可选同说话人连续参考 cue 和理由。分句必须完整保留原文顺序；参考仍由分离人声参数包准备。语义决定由调用者提供，服务不猜分句或更换引擎。恢复级别按整组重试、语义分段、近邻参考推进。

执行器复用持久长文本队列，稳定 ID 接回原父任务，子任务保存尝试次数及结果。成功短语不重生成；识别不可用保留音频并等待补检查。全部短语成功才能合并，合并结果携带完整冻结绑定进入唯一气口收口器；合并成功不等于落轨成功。已接受组、已取消或删除恢复结果拒绝自动覆盖。最终保留组合的独立识别与自然度复听仍需单独验收。

### Editorial continuation and derived caption freshness

The production run projection exposes actual main-lane clip membership and uncovered
subtitle IDs independently of candidate quality reports. Partial or multi-candidate
editorial coverage requires Agent reconciliation, rather than authorizing another
whole-group generation. This is a tool-to-Agent handoff, not a human approval gate.

Derived dubbing captions retain their text and identity after source edits. Source
lifecycle reconciliation marks only captions linked to changed clips or intersecting
their old/new timeline ranges as stale; lane mute changes affect that lane's ranges.
Audition solo and unrelated UI changes do not invalidate captions. The whole-input
revision fence still rejects a stale asynchronous subtitle commit.

Default export selection and audio rendering ignore temporary audition solo.
Persisted mute, disabled-media and volume settings still supply the default mix;
explicit export track/lane selections override that default. Solo is excluded from
the export input fingerprint so audition changes cannot invalidate an in-flight
render. Source-media and actual mix changes remain protected by the commit fence.


### Physical dubbing completion and reusable evidence

Generation-stage success remains an unplaced-result fact when its workflow later fails during placement. The read model directs that saved result to local close-out, not automatically to TTS regeneration; completion retains its workflow identity until the target is covered or a valid lane-1 deferral resolves it. Cancelled and explicitly discarded results are not recovery candidates. Capacity deferral closes only that group's automation work: the original requested range must continue beyond it.

`dubbing_production.read_completion` exposes `dubbing-completion-v1` through the read-only `/dubbing/completion` endpoint. It reads actual timeline bindings, managed media headers and persistent workflows; missing audio, unplaced results, overlapping/repeated playback and uncovered current targets prevent completion. Unbounded execution checks the full source duration, not merely the existing plan. Manual clips without current acoustic evidence produce warnings rather than a human approval gate. Modern production readiness uses this same projection; cue-only legacy projects retain their read compatibility projection.

`POST /dubbing/candidates/{candidate_id}/content-evidence` is the explicit public content-observation step for a current successful candidate. It resolves `result_id` through the same candidate/history/workflow binding as placement, hashes the actual audio, and runs the existing no-hint whole-file ASR outside the Project transaction. The transcript is written to the frozen candidate only when the repository revision, plan, text binding, candidate identity and audio hash still match. A complete exact-byte result is cached and returned with a stable `evidence_id`; it is an observation, not semantic, naturalness or primary-track approval.

`POST /dubbing/candidates/{candidate_id}/current-projection` refreshes evidence from the exact saved primary clips through `DubbingProductionApplicationService`. It uses repository/source/plan/audio/projection identity checks and existing word-coverage and capacity rules; it never generates, recognizes, moves or trims audio. Unchanged rendered word relationships retain their existing semantic decisions; changed relationships require fresh decisions. Semantic review merges retained and submitted decisions and still requires complete boundary coverage. Candidate reports describe current evidence rather than an append-only attempt history. See the [domain contract](../../../../docs/domains/video_localization/domain-contract.md) for the public contract.

After safe local gap processing, actual protected-word bounds are compared with the current group/next-anchor window and any existing main-lane neighbour. Admission uses the strict occupied boundary, including sub-frame speech overflow: alignment tolerance cannot turn non-removable speech into retryable padding. Proven physical overflow returns `status=needs_attention` with `required_action=resolve_capacity`; every automatic close-out entry preserves the take and records a durable capacity-decision failure instead of consuming the frozen whole-group retry. An explicit single-group `regenerate_existing=true` decision can still use that existing retry contract.

Explicit `repair_timeline_capacity` also accepts a complete, unplaced candidate. With `ordinary_speed_baseline`, the replacement is bounded to the frozen baseline plus 0.05 rather than the legacy capacity-speed exception. The executor names the exact old workflow receipts through an internal reservation intent; the shared service validates current plan, frozen identity, durable capacity failure and generated result under its write lock. Only those generated-but-unplaced receipts are exempted from occupancy. Earlier placement failures marked `TTS_PLACEMENT_REGENERATION_REQUIRED` or `TTS_PLACEMENT_REGENERATION_EXHAUSTED` can use the same recovery only with that current capacity proof; arbitrary terminal failures are not exempted. After a neighboring text rebase, verified equivalent generated receipts remain available as recovery identities without being projected as current running jobs. Reservation revalidates their frozen synthesis inputs against the current group; historical records remain immutable. Real generation, unrelated receipts and a second concurrent reservation remain blocked. Existing audio is retained; successful adoption closes superseded placement receipts through the existing atomic path.

Rhythm spacing, trailing safety-margin fitting and final capacity checks share the same occupied end boundary, including an existing next primary clip's leading padding. Padding can shrink only outside the union of aligned words and measured speech; the next clip and current audible onset remain unchanged. Once close-out locks a measured onset, selected-group scheduling preserves that projection's source crops and relative slice positions; it may translate the whole projection but cannot reuse global scheduling's newly trimmed padding at the old start. Ordinary handoff clips without a group tag can supply current evidence only after exact candidate, target and revision validation. A newer successful ordinary handoff with current accepted proof supersedes an older managed failure, while a newer failed replacement remains visible.

`POST /dubbing/production-run/manual-timing-deferral` is the only bounded capacity-fallback write. It accepts a current successful history `result_id` resolved through `generated_candidates` or the canonical TTS workflow; `artifact_id` is CQC evidence and is not a history result identity. The command verifies the current Project revision, unchanged compressed text, full target/cue bindings, current audio hash and header duration, content evidence and its stable public reference, speech bounds, the actual current-group/next-anchor window, and one evidence-backed disposition for every recovery strategy. It then reuses the shared managed-media adoption and frozen-result placement path to append the full uncropped audio on `dub_lane=1`. It preserves every existing primary clip and subtitle result mirror, records the Agent's semantic and listening assertions without creating a CQC pass, and is idempotent by request fingerprint. In the same Project transaction, the selected generated workflow's placement stage is closed against the lane-1 clip while its generation/result identity remains unchanged; this does not create a primary CQC pass. A full history candidate is required; a non-contiguous edited projection must first be rendered through the existing managed-media path and cannot be silently expanded back to removed speech.

Deferral admission is a server-owned placement decision, not a request-level duration comparison. It accepts proven duration overflow or a protected-speech collision with another target's primary clip. Close-out and deferral share `first_protected_audio_overlap`: aligned words and earlier VAD activity form the protected envelope, independently of the unchanged word placement anchor. Removable padding alone, other lanes and the group's own retained takes do not establish a collision fallback. Receipts add `placement_failure_reason` and `conflicting_clip_ids`; legacy receipts read as duration overflow with no recorded collisions. The request shape and fingerprint remain unchanged, preserving idempotent v1 replay.

When adjacent context invalidates a receipt, a fresh command may revalidate the same managed lane-1 clip after obtaining current candidate/content and recovery evidence. The shared deferral validator checks its identity, bindings, audio hash and exact expected full-file projection before saving a new receipt. This path copies no media and preserves every timeline field; changed or duplicate clips remain conflicts. An old idempotent request still cannot resurrect a deleted clip or invent current proof.

Completion reports valid lane-1 dispositions in `deferred_manual_timing_group_ids` and `deferred_manual_timing_clip_ids`. Such a result keeps physical delivery `incomplete`, while `automated_production_status=resolved` tells the executor that remaining work is manual timing rather than another TTS request.

Text edits and explicit replanning reuse the same deferral-retention function. Rebinding requires unchanged group and adjacent context, spoken text, full-audio hash, target/cue binding and exact parked projection; deleted or edited material never becomes a new pass. A receipt left at an older editorial revision may recover only through those saved dependency proofs, keeping its original evidence revision, recovery decisions and listening status. No audio is regenerated or re-placed.

All completion disposition lists and automated group checks use the requested subtitle range. Unstarted groups outside that range do not block bounded completion; a later full-range check still includes them. A currently valid deferral supersedes the group's historical capacity failure and older unplaced results for the same resolved targets without accepting any retained primary take. Other missing targets and running replacement tasks remain visible.

A workflow with a successful generation stage and a persisted result resumes through `process_gaps` while placement remains active. A current semantic audit takes precedence and supplies its specific Agent action; an active generation or unknown result continues to wait. Workflow activity alone does not prove that synthesis is still running.

A pending staged take that now overlaps a saved neighbouring primary clip returns to `process_gaps` before semantic adoption. The read model and atomic adopter share the same primary-lane collision predicate in `dubbing_timeline_edit_gate`; staging omits media paths but still checks actual playable neighbours. This invalidates only local placement work, not generated audio or already accepted neighbouring takes.

`dubbing_plan_continuation` retains verified completion evidence across revisions only when the group's local source/adjacent context, audio bytes and retained timeline projection are unchanged. Trusted frozen CQC inputs record their dependency fingerprint and original evidence revision. Inputs without this fingerprint cannot acquire cross-source acceptance. No reuse creates a new listening or human confirmation record.
